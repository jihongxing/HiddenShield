# 音频噪声底频带选择实验设计

更新时间：2026-07-02

实验代号：`audio_noise_floor_band_selection_experiment`

## 1. 目标

本实验只针对稳定噪声底 profile，例如 `field_recording_noise_floor`，验证是否能把 `field-noise` 当前集中在 watermark 频带的差异能量迁移到更适合噪声底掩蔽的子频带或时间窗口，同时保持正式能力不退。

必须守住：

- payload 格式不变：继续使用 V3/39 minimal anchor 与现有 recovery packet。
- 版权编号不变：继续使用完整 128-bit `HS-XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX`。
- 跨端可读不变：候选产物必须能被当前正式 extractor 读回；需要新 extractor 才能读回的方案只能作为研究对照，不得晋级。
- 提取置信度不退：`extractionConfidence >= 0.99`，目标保持 `1.000000`。
- 质量阈值不降：full gate 音频 SNR 阈值继续为 `44 dB`，不得以阈值例外制造通过。

## 3. 触发边界

实验策略只能在稳定噪声底 profile 下生效，且不得按样本名硬编码。触发条件沿用当前 `watermark-core` 噪声底 profile 语义：

| 条件 | 要求 |
| --- | --- |
| RMS mean | `0.06..=0.11` |
| RMS span ratio | `<= 0.035` |
| low energy frame ratio | `<= 0.05` |
| transient frame ratio | `<= 0.05` |
| noise-like frame ratio | `0.35..=0.90` |

任何不满足该 profile 的音频，包括 `voice`、`music`、`quiet`、`transient`、`speech-music-mix` 和 L1 视频音轨，必须继续走现有正式路径。

## 4. 候选组

所有候选组都必须保留现有 `audio_band_bins`、recovery bit-slot、3-lane majority 和当前 extractor 可读布局。实验只改变稳定噪声底 profile 下的“哪些 lane / frame / 子频带优先写入”，不能改变 payload 编码、UID、packet 长度、bit 顺序或正式质量阈值。

| 组别 | 名称 | 频带 / 时间窗口策略 | 目的 | 晋级前提 |
| --- | --- | --- | --- | --- |
| A | `inner_watermark_subband_sparse` | 仍在现有 2-8 kHz watermark 频带内写入，但优先选择当前 recovery 可读布局中靠中段、原始能量更高且 pair margin 更稳定的 lane；继续 sparse lane-majority。 | 验证是否能在不动 extractor 的前提下降低局部能量重分配尖峰。 | `field-noise` SNR 明显高于 `13.4966 dB`，`extractionConfidence >= 0.99`，常规音频不触发。 |
| B | `frame_stability_window_sparse` | 频带不变，按 1 秒分段 SNR、短时 RMS span 和 spectral flatness 选择最稳定的噪声底时间窗口；跳过局部分段 SNR 最差的 frame，但保持 recovery packet 覆盖完整。 | 验证低 SNR 是否由少数时间窗口承担过多差异能量导致。 | 分段 SNR min 抬升，spread 下降，且 full packet 仍可读。 |
| C | `masked_pair_budget_cap` | 频带不变，对稳定噪声底 profile 增加每秒 pair budget 上限；当某秒 watermark-band noise share 预测过高时，把剩余写入推迟到后续稳定窗口。 | 验证限制单位时间差异能量集中度能否改善 SNR 和 ABX。 | `bandEnergyShare.watermark.noise` 下降，`modifiedPairRatio` 不高于当前 `0.284046`，提取置信度不退。 |

研究对照组可以记录“迁出 2-8 kHz 主频带”的结果，但只用于判断方向，不得进入正式候选。原因是这类方案通常需要 extractor 同步改动，违反当前“跨端可读不变”的约束。

## 5. 指标矩阵

每一组候选都必须与 baseline 对照，至少输出以下字段：

| 字段 | 要求 |
| --- | --- |
| `candidateId` | `baseline` / `inner_watermark_subband_sparse` / `frame_stability_window_sparse` / `masked_pair_budget_cap` |
| `profileMatched` | 是否命中稳定噪声底 profile |
| `payloadProtocolVersion` | 必须为 `3` |
| `payloadBytesLength` | 必须为 `39` |
| `copyrightIdFormat` | 必须为 `HS-XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX` |
| `extractPassed` | 必须为 `true` |
| `extractionConfidence` | 必须 `>= 0.99` |
| `snr` | 与 baseline 和 `44 dB` 阈值对比 |
| `segmentedSnr.min/mean/max/spread` | 判断是否改善局部低 SNR |
| `bandEnergyShare.low/watermark/high.signal` | 原始信号频带占比 |
| `bandEnergyShare.low/watermark/high.noise` | 保护副本差异频带占比 |
| `modifiedPairRatio` | 不得高于当前稀疏实验基线 |
| `peakDelta` / `lufsDelta` / `newClipping` | 不得触发 full gate 阻断 |
| `abxCorrectRate` | 人工 ABX 正确率，平均不得高于 `60%` |

## 6. ABX 记录

实验必须生成独立 ABX 表，不覆盖 full gate 正式 `abx/audio_abx_trials.csv`。建议路径：

```text
watermark-core/target/audio-noise-floor-band-selection/run-<runId>/abx/audio_noise_floor_band_selection_abx_trials.csv
```

CSV 字段：

```csv
runId,candidateId,sampleId,profile,device,environment,trial,A,B,X,answer,correct,confidence_1_5,perceivedDifference,notes
```

ABX 执行规则：

- 至少 5 人，每人每个候选至少 3 轮。
- 设备覆盖 `headphones` 和 `speaker`。
- 环境覆盖 `quiet-room` 和 `office`。
- 不允许记录者提示 A/B 哪个是保护副本。
- 若任一候选平均正确率高于 `60%`，该候选阻断。
- ABX 只能作为“无稳定可闻差异”的补证，不能替代 SNR、LUFS、peak、clipping 和 extraction confidence。

## 7. 通过 / 阻断规则

候选组晋级条件：

1. 仅稳定噪声底 profile 触发，常规音频与 L1 视频音轨不触发。
2. `payloadProtocolVersion=3`，`payloadBytesLength=39`，版权编号格式不变。
3. 当前正式 extractor 可读，且 `extractionConfidence >= 0.99`。
4. release gate 必须通过。
5. full gate 不得新增除 `field-noise` 以外的阻断项。
6. `field-noise` SNR 必须高于当前 `13.4966 dB`；若仍低于 `44 dB`，必须继续 blocked，并附 ABX 原始记录与是否继续实验的判断。
7. 不得降低 `44 dB` SNR 阈值，不得把单人听感写成通过依据。

阻断条件：

- 任一正式样本提取失败。
- `extractionConfidence < 0.99`。
- 非稳定噪声底 profile 被错误触发。
- `modifiedPairRatio` 高于当前稀疏实验基线。
- `bandEnergyShare.watermark.noise` 仍接近 `1.0` 且 SNR 无改善。
- 任一候选 ABX 平均正确率高于 `60%`。
- 需要改变正式 extractor 才能读回。

## 8. 实施建议

建议实现为独立实验入口，不接入正式 UI / mock / 自动化正式路径：

```powershell
npm run watermark:audio-noise-floor-band-selection-experiment -- --run-id codex-noise-band-selection-1
```

建议输出：

```text
watermark-core/target/audio-noise-floor-band-selection/run-<runId>/
  experiment.json
  experiment.md

    baseline/control.wav
    baseline/protected.wav
    frame_stability_window_sparse/protected.wav
  abx/audio_noise_floor_band_selection_abx_trials.csv
```

实验实现建议：

1. 先复用当前 `field-noise` deterministic sample，生成 baseline。
2. 对候选 A/B/C 分别生成 protected WAV。
3. 对每个 protected WAV 运行当前正式 extractor 和 readonly candidate extractor。
4. 复用 full gate 的 SNR、LUFS、peak、clipping、`perceptualDiagnosis` 计算逻辑。
5. 输出候选对比表和 ABX CSV。
6. 只有候选满足晋级条件后，才允许讨论是否把对应策略纳入 `watermark-core` 正式路径。

## 10. 当前推荐结论

优先实现 B 组 `frame_stability_window_sparse` 的实验版本，因为它最小化对频带布局的影响，只改变稳定噪声底 profile 下的时间窗口选择，最有机会在保持现有 extractor 可读的前提下改善分段 SNR。

如果 B 组无法降低 `bandEnergyShare.watermark.noise` 或提升 SNR，再实现 A 组；C 组作为控制单位时间差异能量集中度的补充实验。任何需要迁出当前 2-8 kHz extractor 频带的方案，都必须另开跨端读取迁移设计，不能混入本实验。

## 13. C 组 masked_pair_budget_cap 实验记录

执行时间：2026-07-02

实现内容：

- C 组 `masked_pair_budget_cap` 已接入独立实验入口。
- 实验仍限制在当前 2-8 kHz / 现有 extractor 可读布局内，不改 payload、版权编号、recovery packet、bit 顺序、跨端读取路径或正式质量阈值。
- 实验先用正式 `WatermarkService::embed` 生成 baseline，再按 1 秒窗口统计 recovery pair 差异能量；在每秒内优先回退最高差异 pair，只保留当前 extractor 仍可读的预算比例。
