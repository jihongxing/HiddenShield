# HiddenShield 商业模式规划

> 发布清扫说明：本文是历史商业模型规划，不是对外销售页或当前权益承诺。自 2026-07-31 起，套餐、商品、能力权益和 legacy mapping 的唯一执行口径为 `docs/商业套餐与权益全局语义设计.md`；当前封版、销售、法务和研发能力边界以 `docs/当前真实能力边界说明.md`、`docs/商业化落地Roadmap.md` 为准。不得据此声明 L3 视频画面盲水印、生产 C2PA / TSA、生产 PostgreSQL 或真实支付已经上线。

## 2026-07-31 当前模型取代说明

本文下方的 Free / Creator / Studio / Enterprise 分层是历史产品提案，已不再作为新功能、UI、支付、授权或文档的全局术语。

- 用户可见桌面产品固定为“未付费”和“图片 / 音频年度授权”。
- 正式报告是单份商品，不随年度授权自动开放。
- 云同步是图片 / 音频年度授权的内含权益；独立云版权库 UI 是该权益的未来产品界面，不另设第三档个人套餐。
- 团队、企业 API、云端批量和云视频是未来独立 capability entitlement 或组织合同产品线。
- 历史 `creator`、`studio`、`enterprise` 仅能用于兼容读取、历史证据和明确标记的内部 fixture。

后续历史内容保留用于追溯，不得覆盖本节或 `docs/商业套餐与权益全局语义设计.md` 的当前决策。

## 1. 总体判断

HiddenShield 适合做成 **订阅为主、按需增购为辅、企业定制兜底** 的商业模型。

核心原则：

1. 本地基础能力尽量保持低门槛，负责获客和留存。
2. 订阅负责把“单机工具”升级成“跨设备创作与版权工作台”。
3. 未来的视频盲水印云端能力，适合单独做成高毛利增值层。
4. 真正值钱的不是单次写入，而是持续使用、跨端同步、团队协作、证据输出和云端算力。

## 2. 商业主线

### 主线 A：订阅

订阅是主收费模型，负责覆盖：

- 图片/音频水印写入与验证的高频使用
- 版权库长期保存
- 移动端与桌面端同步
- 批量处理
- 证据报告导出
- 优先队列和高级支持

建议采用：

- 月付
- 年付
- 团队按席位
- 企业定制

### 主线 B：未来视频云端盲水印

视频云端盲水印不建议和本地基础功能混卖，而应作为独立高级能力：

- 云端算力成本更高
- 处理链路更长
- 适合做成“订阅 + 额度”或“订阅 + 额外包”

建议收费方式：

- 按分钟额度
- 按队列任务数
- 按导出成品数
- 订阅内含基础额度，超额再购买

### 主线 C：企业与定制服务

面向：

- 工作室
- MCN
- 法务/版权团队
- 平台合作方

未来可售方向，需完成开通验收和当前能力边界确认：

- 私有化部署
- API 接入
- 白标报告
- 团队权限
- 审计日志
- 经合同和生产 readiness 验收后的 SLA

## 3. 产品分层

### Free

目标：获客、降低试用门槛。

建议包含：

- 本地图片/音频写入与验证
- 本地版权库
- 基础取证
- 单设备使用

建议限制：

- 不开放云同步
- 不开放团队协作
- 不开放视频云端能力
- 不开放批量高级能力

### Creator

目标：个人创作者主力付费层。

建议包含：

- 图片/音频完整写入与验证
- 版权库长期保存
- 移动端 + 桌面端同步
- 批量处理
- 证据报告导出
- 更高同步配额
- 优先处理队列

### Studio

目标：团队和工作室协作。

建议包含：

- 多席位
- 共享版权库
- 统一创作者身份
- 权限管理
- 审计记录
- 团队同步额度

### Enterprise

目标：大客户和深度集成。

建议包含：

- 私有化部署
- API / SDK
- 单点登录
- 审计与合规
- 专属支持
- 定制化视频云处理

## 4. 当前功能如何变现

当前已经具备或接近具备的能力，建议这样分工：

| 能力 | 当前状态 | 商业定位 |
| --- | --- | --- |
| 图片盲水印写入 / 验证 | 当前核心能力 | Free 可用，批量和报告进订阅 |
| 音频盲水印写入 / 验证 | 当前核心能力，30 秒以上音频边界 | Free 可用，批量和报告进订阅 |
| 本地版权库 | 当前核心能力 | Free 可用，长期/跨端进订阅 |
| 完成后验证状态 | 当前可信度增强能力 | 随写入能力提供，不单独收费 |
| 云同步 | 已进入产品设计和实现主线 | Creator 起订阅权益 |
| 统一创作者身份 | 已进入同步模型 | Creator 起订阅权益 |
| 本地批量处理 | 当前已有订阅规划 | Creator 起订阅权益 |
| 云端批量处理 | 未来能力 | 高阶订阅 + 额度 |
| 视频云端盲水印 | 未来能力 | 独立高阶权益 + 额度 |
| 团队共享版权库 | 未来团队能力 | Studio 起权益 |
| API / 私有化 | 未来企业能力 | Enterprise |

### 适合放进订阅的

- 图片写入 / 验证
- 音频写入 / 验证
- 版权库长期保存
- 跨端同步
- 完成后验证状态留存
- 本地批量处理
- 证据摘要 / 报告导出

### 更适合做成加值层的

- 云端视频盲水印
- 大批量处理配额
- 团队席位
- 更长历史留存
- 专属同步存储
- 企业审计

### 不建议过度商业化的

- 本地基础写入入口
- 本地验证入口
- 本地版权库最小可用能力

原因很简单：这些是用户进入产品的“底座”。底座一旦太贵，订阅转化会很差。

## 5. 未来视频盲水印的商业打法

视频能力建议走云端化：

- 计算重
- 适合排队
- 适合做异步任务
- 适合和订阅额度绑定

建议产品结构：

1. 订阅包含基础视频处理额度。
2. 超额任务按包购买。
3. 高并发和优先队列单独收费。
4. 大客户可走私有云或专属集群。

这类能力最适合卖：

- “更稳”
- “更快”
- “更大规模”
- “更少人工”

而不是单纯卖“算法名词”。

## 6. 批量处理订阅服务设计

批量处理可以作为 HiddenShield 最先落地的订阅服务，因为它天然代表“效率提升”，用户也容易理解为什么要付费。

### 6.1 产品定位

批量处理不是新的水印算法，而是把现有图片 / 音频能力包装成更省时间的工作流。

适合售卖的价值：

- 一次处理多个文件。
- 队列自动执行。
- 每个文件都有完成后验证。
- 失败文件可单独重试。
- 处理结果自动进入版权库。
- 支持统一创作者身份和更新说明。

### 6.2 免费版边界

Free 保留单文件处理：

- 单张图片写入。
- 单个音频写入。
- 单文件验证。
- 本地版权库记录。

Free 不开放批量执行能力，也不提供小批量试用。产品内可以保留批量入口，但点击后只展示订阅说明、权益差异和升级入口，不进入文件选择或队列执行。

这样可以保证免费用户能体验核心能力，同时让高频用户自然感受到订阅价值。

产品原则：**单文件本地处理是免费入口，本地批量处理是 Creator 订阅权益。**

### 6.3 Creator 批量权益

Creator 订阅开放本地批量：

- 批量图片写入。
- 批量音频写入。
- 批量验证。
- 批量重试。
- 批量导出结果摘要。
- 本地后台队列。
- 可暂停 / 取消。

建议不按本地批量次数扣点。原因是本地批量没有明显云端边际成本，订阅用户应该感受到“订阅期内放心用”。

### 6.4 Studio 批量权益

Studio 在 Creator 基础上增加团队批量能力：

- 团队共享批量任务记录。
- 批量任务按成员归属。
- 统一创作者档案。
- 批量报告导出。
- 团队级失败审计。
- 更高并发上限。

### 6.5 云端批量与视频批量

云端批量和视频批量必须与本地批量分开设计。

本地批量：

- 走用户自己的设备。
- 适合放进订阅。
- 不建议按次扣点。

云端批量：

- 消耗服务器算力。
- 适合订阅内含额度 + 超额包。
- 视频按分钟数计费。
- 图片 / 音频云端批量可按任务数或文件数计费。

### 6.6 批量任务计量规则

建议统一规则：

- 成功完成才计入用量。
- 用户主动取消不计入用量。
- 程序崩溃不计入用量。
- 文件格式不支持不计入用量。
- 云端任务失败不扣额度。
- 已完成的单个文件可以入账，失败项独立标记。

### 6.7 批量服务体验要求

批量作为订阅服务，必须做得像成熟产品，而不是简单循环执行。

最小体验要求：

- 队列列表。
- 当前进度。
- 成功 / 失败 / 跳过统计。
- 失败原因。
- 单项重试。
- 全部重试。
- 取消任务。
- 输出目录管理。
- 完成后自动写入版权库。

### 6.8 权益命名

建议产品内不要写“解锁算法能力”，而写：

- 批量处理
- 批量写入
- 批量验证
- 队列管理
- 失败重试

更像工具能力，也更符合用户付费直觉。

## 7. 其他可商业化方向

### 7.1 证据与报告

- PDF 版权报告
- 配置后的 TSA / 网络授时辅助报告
- 法务版摘要
- 批量导出

可作为 Creator 或 Studio 的高阶权益。

### 7.2 同步与存储

- 同步设备数
- 同步空间
- 历史留存天数
- 云端审计留痕

适合作为订阅分层或加购项。

### 7.3 团队协作

- 多席位
- 共享版权库
- 审批流
- 权限分级

适合 Studio / Enterprise。

### 7.4 定制服务

- 私有化部署
- 品牌定制
- 接口集成
- 咨询与迁移服务

适合高客单价客户。

## 8. 套餐与权益设计

建议先采用“免费 + 个人订阅 + 团队订阅 + 企业定制”四层结构。价格先作为内部验证口径，正式上线前再根据种子用户反馈调整。

| 层级 | 建议价格 | 核心用户 | 核心价值 |
| --- | ---: | --- | --- |
| Free | 免费 | 偶发创作者、试用用户 | 本地可用，理解产品价值 |
| Creator | 29-49 元/月，199-399 元/年 | 个人创作者 | 跨端版权库、批量、报告 |
| Studio | 99-199 元/月/席位 | 工作室、MCN 小团队 | 团队共享、权限、审计 |
| Enterprise | 面议 | 大客户、平台、法务团队 | 私有化、API、验收后的 SLA |

Free 用户可单独购买报告类商品：

| 商品 | 价格 | 说明 |
| --- | ---: | --- |
| 单份版权详细报告 | 19.9 元 / 份 | 针对单条版权记录生成完整版权辅助报告 |
| 维权证据包 | 49.9 元 / 份 | 在版权详细报告基础上组织侵权链接、截图、平台、发现时间和证据清单 |

### 8.1 Free 权益

Free 不应该做成“残废版”，否则用户无法理解核心价值。

建议包含：

- 本地图片写入与验证。
- 本地音频写入与验证。
- 本地版权库。
- 单设备创作者身份。
- 基础完成后验证。

建议限制：

- 不提供云同步。
- 不提供批量处理。
- 未购买时不提供版权详细报告 / 维权证据包；购买后仅开放对应记录或案件的报告。
- 不提供团队共享。
- 不提供未来视频云端盲水印。

### 8.2 Creator 权益

Creator 是主收入层，应该覆盖个人创作者最常见的长期需求。

建议包含：

- Free 全部能力。
- 桌面端 + 移动端云同步。
- 创作者身份跨端同步。
- 订阅权益跨端同步。
- 批量图片 / 音频处理。
- 批量队列管理和失败重试。
- 版权库长期保存。
- 版权报告导出。
- 订阅内包含常规单条版权详细报告导出，Free 单份报告购买可作为升级 Creator 的前置体验。
- 更完整的取证记录。
- 优先技术支持。

### 8.3 Studio 权益

Studio 面向多人协作，不只是把 Creator 乘以人数。

建议包含：

- Creator 全部能力。
- 多席位。
- 共享版权库。
- 团队创作者档案。
- 成员权限。
- 审计日志。
- 团队级同步额度。
- 统一账单。
- 更高批量并发上限。

### 8.4 Enterprise 权益

Enterprise 不公开固定价格，按客户需求报价。

建议包含：

- 私有化部署。
- API / SDK。
- 单点登录。
- 专属云端视频处理资源，需另行合同、开通验收和当前能力边界确认。
- 专属技术支持。
- 数据合规审计。
- 合同级 SLA，不能覆盖尚未完成生产 readiness 的 L3、生产 C2PA / TSA、生产 PostgreSQL 或真实支付链路。

## 9. 视频云端盲水印商业模型

视频云端盲水印是未来高价值能力，不建议首期免费大规模开放。

### 9.1 计费单位

建议优先按“处理分钟数”计费，而不是按文件数计费。

原因：

- 1 个 10 秒视频和 1 个 2 小时视频的成本完全不同。
- 云端 GPU / CPU / 存储 / 队列时间都更接近视频时长。
- 用户也容易理解“每月包含多少分钟”。

### 9.2 套餐额度

建议结构：

| 套餐 | 视频云额度 | 超额方式 |
| --- | ---: | --- |
| Free | 无 | 不开放 |
| Creator | 少量体验额度 | 购买分钟包 |
| Studio | 团队共享额度 | 购买分钟包 / 升级套餐 |
| Enterprise | 合同额度 | 定制 |

### 9.3 视频任务增购包

可选增购：

- 100 分钟包。
- 500 分钟包。
- 2000 分钟包。
- 优先队列包。

扣费规则：

- 只对成功完成的云端视频任务扣额度。
- 用户取消、任务失败、服务异常不扣额度。
- 输出多个版本时按实际处理链路计费，避免暗扣。

### 9.4 视频能力上线顺序

1. 内测：仅开放给少数 Creator / Studio 用户。
2. Beta：开放小额度体验，验证成本与稳定性。
3. 正式：进入订阅权益和增购包。
4. 企业：开放专属队列和私有化方案。

## 10. 功能与付费边界

### 10.1 不建议收费拦截的功能

- 本地单文件图片写入。
- 本地单文件音频写入。
- 本地验证。
- 本地版权库基础记录。

这些功能是用户理解产品价值的入口。

### 10.2 适合一次性付费的功能

- 单份版权详细报告：19.9 元 / 份。
- 维权证据包：49.9 元 / 份。

这些功能对应强触发、低频但高意愿的维权场景。Free 用户可以先免费积累版权记录，需要平台申诉或举报材料时再按份购买。

一次性付费不能改变订阅等级，也不能解锁批量、云同步或团队能力。

### 10.3 适合订阅拦截的功能

- 云同步。
- 本地批量处理。
- Creator 订阅内常规报告导出。
- 多设备恢复。
- 长期版权库留存。
- 团队共享。

这些功能表达的是持续价值。

### 10.4 适合额度计费的功能

- 云端视频盲水印。
- 云端批量处理。
- 高优先级任务。
- 大规模报告生成。

这些功能有明确边际成本。

## 11. 权益系统建议

当前项目已经有本地权益状态和用量账本基础，应继续沿用模块化 entitlement 思路。

建议 features：

| feature | 说明 | 计费属性 |
| --- | --- | --- |
| `cloud_sync` | 云同步 | 订阅 |
| `batch_processing` | 本地批量处理 | 订阅 |
| `cloud_batch_processing` | 云端批量处理 | 订阅 + 额度 |
| `report_export` | 报告导出 | 订阅 |
| `team_workspace` | 团队空间 | 团队订阅 |
| `cloud_video_processing` | 云端视频处理 | 订阅 + 额度 |
| `priority_queue` | 优先队列 | 高阶订阅 / 增购 |
| `api_access` | API 接入 | 企业 |

权益判定原则：

- 客户端可以缓存权益快照。
- 云端能力必须以服务端权益为最终裁判。
- 本地失败、取消、崩溃不记入用量。
- 不上传原始媒体作为订阅校验条件。

## 14. 风险控制

1. 不要把本地核心能力直接锁死，否则获客会很差。
2. 不要把视频云端能力和本地基础功能混成一个价格桶，否则成本不透明。
3. 不要让同步、账户、创作者身份各自独立收费，否则用户会觉得割裂。
4. 不要卖技术词，卖结果。
5. 不要承诺短音频片段一定可恢复完整版权信息。
6. 不要把未实现的视频云端能力写成当前已支持能力。
7. 不要默认上传原始图片、音频、视频。
8. 不要把本地批量和云端批量混为一种计费模型。
9. 不要对失败批量任务扣额度。

## 15. 对外表达

建议对外不要主打“DWT / FFT / 16 切片 / HMAC”等技术词。

更适合的表达：

- 发布前保护作品。
- 手机和电脑版权库自动同步。
- 发现盗用后快速取证。
- 一次处理整批作品，失败项可单独重试。
- 团队统一管理原创作品。
- 视频高级保护未来可由云端完成，当前不作为已上线承诺。

## 16. 结论

HiddenShield 最合理的商业模式是：

**本地基础能力做入口，订阅做主收入，视频云端做高毛利增量，团队和企业做规模化收入。**

这套结构既能覆盖当前图片/音频能力，也能自然承接未来的视频盲水印云服务。
