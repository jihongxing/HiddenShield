# HiddenShield 双端版权记录字段一致性契约

更新时间：2026-06-29

本文档用于锁定“桌面端字段 -> 移动端字段 -> 同步 payload -> 报告字段”的同一语义链路。它不是 UI 展示清单，而是版权库、同步、报告和跨端互验的字段契约。

核心判断：

- 桌面端 SQLite `user_version` 和移动端 SQLite `_databaseVersion` 可以不同；版本号只代表各端本地迁移历史。
- 双端一致性看字段语义、持久化、同步 payload、报告表达和冲突处理是否一致。
- 任一字段进入版权库详情、存证摘要或正式报告前，必须先能在本端持久化；任一字段进入云同步 payload 前，接收端必须能解析并落库或明确写入等价字段。
- `protectedCopyPath`、原始媒体路径、保护副本本地路径、bundle 本地路径不进入同步 payload 和正式报告。
- 任何本地路径字段都禁止进入同步 payload 和正式报告；如需跨端理解，只能同步安全名称、摘要或不可逆元数据。

## 1. 契约范围

本契约覆盖当前可承诺的版权记录共享字段：

- 记录身份与版本链。
- 保护副本与输出策略。
- Payload V2 与后端登记状态。
- 作品声明与授权策略。
- 写入后验证、可信时间和第三方验证。
- L2 视频指纹存证元数据。
- L3 视频画面盲水印收据元数据。

V3 media payload 正式接入前，还必须同时遵守 `docs/V3跨端fixture与迁移桥接报告字段冻结合同.md`。该合同冻结 V3 fixture、V2 迁移桥、报告显示差异和回滚门禁，并由 `rights:v3-migration-contract` 做机器检查；本文档只负责字段链路，不代表 V3 正式写入已经上线。

不在本契约内的本地字段：

- 桌面端本地 `protected_copy_path`。
- 桌面端 `thumbnail_path`、旧平台输出路径和旧平台 hash。
- 移动端本地分享 intent、系统文件选择结果和运行态 UI 状态。
- 原始媒体、保护副本媒体本体和任何本地绝对路径。

## 2.1 V3 迁移期字段来源冻结

V3 不新增一套完整授权字段，也不把训练许可重新放回媒体 payload。V3 正式接入后，上表中的共享字段仍复用同一同步 key 和报告字段，但字段来源必须按下表解释：

| 字段 | V2 迁移桥来源 | V3 来源 | 报告显示 |
| --- | --- | --- | --- |
| `watermark_uid` | V2/119 payload 读取 | V3 最小锚点读取 | 版权编号 |
| `payload_protocol_version` | V2 payload，固定 `2` | V3 payload，固定 `3` | Payload 协议 |
| `payload_bytes_length` | V2 payload，固定 `119` | V3 codec 正式长度 | Payload 协议 |
| `media_payload_role` | 由 V2 协议版本派生为 `v2_full_record` | 由 V3 协议版本派生为 `v3_minimal_anchor` | 媒体载荷角色 |
| `payload_auth_status` | V2 payload auth 校验 | V3 `auth_tag` 校验 | Payload 认证状态 |
| `revision` | V2 旧字段桥接或本地 / registry 记录 | 本地 / registry 版本链 | 版本次数 |
| `parent_watermark_uid` | V2 旧字段桥接或本地 / registry 记录 | 本地 / registry 版本链 | 上一版编号 |
| `watermark_id_issue_mode` | V2 旧字段桥接或登记记录 | 本地 / registry 登记记录 | 编号签发模式 |
| `training_permission_declaration` | V2 coarse bit 只作旧记录兜底，优先 registry | registry / 云版权库 | 训练许可声明 |
| 其他作品声明字段 | V2 快照只作旧记录兜底，优先本地 / registry | 本地 / registry / 公开元数据 | 创作者声明 |

迁移期报告必须区分 `V2 / 119 bytes` 的“旧记录迁移桥”与 `V3 / <length> bytes` 的“最小锚点”。当前 `watermark-core` payload 层已具备 `decode_watermark_payload_readonly`，可在 bytes 层识别 V2/119 与 V3/39 minimal anchor；`rights:v3-readonly-fixture-qa` 已用受控 image/audio anchor bytes 和 staged PNG/WAV fixture 容器验证桌面 / 移动 bridge 能保留 `watermarkUid + payloadProtocolVersion=3 + payloadBytesLength=39 + payloadAuthStatus=verified`；图片 sync packet 与音频 recovery packet 已有 V3/39 packet 单测，并保留显式 readonly candidate reader 作为迁移桥 / 受控 QA 入口。默认 `WatermarkService::embed/extract`、桌面 scheduler、桌面默认验证页和 Android 原生 bridge 默认 `write/read` 已切到 V3/39；V2/119 只通过显式迁移 / rollback 工具链读取或写入。正式报告生成器与同步回填 QA 已把派生 `media_payload_role` 纳入 V2/V3 迁移桥字段，V2 显示 `v2_full_record`，V3 显示 `v3_minimal_anchor`。该字段不入媒体 payload、不入数据库，仍由协议版本派生；iOS 默认 V3 运行态 QA 因缺少 macOS + Xcode + iOS Simulator 或真机环境仍挂起。`payload_auth_status=verified` 只表示媒体锚点校验通过，不表示法律授权有效；训练许可展示必须继续来自 registry 或版权库声明，并保持非法律结论边界。

## 3. 必须保持的机器合同

`npm run dual:contract` 必须检查：

- `src-tauri/src/sync/storage.rs` 的 `VAULT_RECORD_SYNC_PAYLOAD_KEYS` 与 `mobile_app/lib/app/mobile_app_state.dart` 的 `vaultRecordSyncPayloadKeys` 共享同一套字段。
- 桌面端生成云同步 payload 时包含上述共享字段。
- 移动端 `VaultRecord.toSyncPayload()`、远端解析 `RemoteSyncChange.fromJson()` 和 `RemoteSyncChange.toVaultRecord()` 不丢字段。
- 桌面端 `VaultRecord`、SQLite schema、`VAULT_COLUMNS`、插入查询和移动同步接收入库路径都覆盖需要持久化的字段。
- 移动端 `VaultRecord`、SQLite schema、`_recordToRow()`、`_recordFromRow()` 都覆盖需要持久化的字段。
- 桌面正式报告和移动正式报告草稿都从记录字段读取，而不是只写静态展示文案。

补充运行态测试：

- 桌面端 `record_sync_event_upserts_mobile_vault_record` 必须构造包含保护副本、payload registry 和作品声明的移动端 payload，并断言桌面端入库后字段仍存在。

## 4. 新字段准入规则

以后任何一端新增版权记录共享字段，必须按此顺序修改：

1. 更新本文档对照表，明确桌面字段、移动字段、payload key、报告字段和隐私边界。
2. 同步更新桌面端模型、DB schema、查询、写入流水线、同步发送和同步接收。
3. 同步更新移动端模型、DB schema、本地存储、同步发送和同步接收。
4. 更新桌面正式报告、移动正式报告草稿和存证摘要。
5. 更新 `dual:contract` 字段合同；合同通过后才允许进入运行态 QA。

禁止做法：

- 只在某端 UI 展示，不入库。
- 只在同步发送端加字段，接收端不解析或不落库。
- 只在报告里写静态文案，不从版权记录读取字段。
- 把本地路径、媒体文件或保护副本文件本体塞进同步 payload。
