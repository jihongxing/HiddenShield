# HiddenShield 商业化契约与权益模型

本文档定义桌面端与云端共享的商业化字段、权益含义和接口约束。移动端当前冻结，历史字段仅保留兼容。

## 2026-07-16 冻结权益矩阵

当前产品不再采用 Free / Creator / Studio / Enterprise 四套餐作为发布口径，只保留“未付费 / 图片音频年度基础权益”两种基础状态。

| 权益 | 未付费 | 图片 / 音频年度基础权益 |
| --- | --- | --- |
| 图片 / 音频单文件处理与验证 | true | true |
| 本地版权库 | true | true |
| `batch_processing` | false | true |
| `report_export` | false | false |
| 正式报告 | 记录级单独购买 | 记录级单独购买 |
| 视频 | 当前不可用 | 当前不可用；未来独立收费 |

约束：

- 年度基础权益按年激活 / 续期；离线 HSLIC1 最长 365 天。
- HSLIC1 V1 继续使用兼容代码 `creator_offline`，但展示名必须是“图片 / 音频年费授权”。
- `creator_offline` 只映射 `batch_processing=true`；`report_export` 必须保持 false。
- 报告由记录级 purchase grant 授权，不得被基础套餐、年费、离线注册码或历史 Creator 状态直接打开。
- 云能力继续由服务端权威决定；未来视频使用独立商品、权益与计费，不复用年度基础权益。
- 后文四套餐矩阵是历史设计记录，不得用于当前客户端展示或发布验收。

## 2026-07-17 基础存证摘要字段合同

基础存证摘要、版权证据技术报告和维权证据包的字段边界以 `docs/基础存证摘要字段矩阵.md` 为唯一事实源。

冻结约束：

- 基础存证摘要对未付费和图片 / 音频年度基础权益用户免费开放，不受 `report_export` 或注册码控制。
- 版权证据技术报告继续由 `copyright_report_single` 记录级 purchase grant 授权。
- 维权证据包继续由 `rights_evidence_pack_single` 记录 / 案件级 purchase grant 授权。
- 基础摘要不得包含价格、套餐、购买状态或营销文案；购买入口继续由版权库 UI 单独展示。
- 原始诊断字段、完整过程链、软件版本、收据摘要、报告签名和 Manifest 只进入已购买报告。
- 本地路径、授权 token、账户秘密、支付秘密和法律结论不得进入任何对外摘要或报告。
- 当前视频字段不得进入图片 / 音频基础摘要。
- 后文历史文档中“Creator 订阅包含报告”的表述不再适用于当前发布基线。

## 1. 目标

- 统一未付费 / 图片音频年度基础权益术语，并保留历史代码兼容边界。
- 统一权益快照、用量账本和额度账本。
- 统一云端返回的 `entitlement.features`。
- 为桌面端和云端提供同一份商业化契约。

### 2.4 feature map

```json
{
  "cloud_sync": false,
  "batch_processing": false,
  "report_export": false,
  "cloud_batch_processing": false,
  "cloud_video_processing": false,
  "priority_queue": false,
  "team_workspace": false,
  "api_access": false
}
```

含义：

- `cloud_sync`: 云同步
- `batch_processing`: 本地批量处理
- `report_export`: 报告导出
- `cloud_batch_processing`: 云端批量处理
- `cloud_video_processing`: 云端视频处理
- `priority_queue`: 优先队列
- `team_workspace`: 团队空间
- `api_access`: API 接入

### 2.5 离线许可证权益源

离线 CDKEY / 本地许可证使用：

- `entitlementSource = offline_cdkey`
- `planCode = creator_offline`（V1 兼容代码）
- `planName = 图片/音频年费授权`

首期固定 feature allowlist：

```json
{
  "cloud_sync": false,
  "batch_processing": true,
  "report_export": false,
  "cloud_batch_processing": false,
  "cloud_video_processing": false,
  "priority_queue": false,
  "team_workspace": false,
  "api_access": false
}
```

规则：

- 离线许可证不得覆盖或伪造云端 `entitlement_state`。
- 本地 feature 可按 `cloud entitlement OR valid offline license` 合并。
- 云端 feature 只能由服务端 entitlement、quota、workspace membership 或 Enterprise API key 决定。
- 后端不得信任客户端上传的 `offline_cdkey` 状态开放任何云能力。
- 单份 purchase grant 继续按记录或案件核销，不进入离线许可证 feature map。
- 详细签名、设备绑定、撤销与实施阶段见 `docs/CDKEY离线激活与本地许可证设计.md`。

Phase K0 主许可证合同：

- 主载体固定为 `HSLIC1.<payload>.<signature>`。
- `payload` 只携带 `creator_offline` 产品代码、安装实例、期限和签发标识，不允许携带任意 feature map。
- 有效许可证必须由客户端把 `creator_offline` 映射到本节固定 allowlist。
- 固定共享向量见 `docs/fixtures/offline-license-k0/hslic1-ed25519-v1.json`。
- 当前合同只用于内部验证，不代表已有可销售的签发和激活流程。

- `occurred_at`
- `feature_name`
- `media_type`
- `file_size_bucket`
- `quantity`
- `event_type`
- `entitlement_status`
- `billing_source`
- `plan_code`

## 5. Quota Ledger

用于云端视频、云端批量、优先队列等消耗型能力。

建议字段：

- `occurred_at`
- `feature_name`
- `quota_type`
- `quota_units`
- `direction`
- `event_type`
- `plan_code`
- `subscription_id`
- `task_id`
- `status`
- `app_version`

规则：

- 只对成功完成的云端任务记账。
- 用户取消、格式不支持、服务异常不扣额度。
- 本地能力不进入 quota ledger。

### 5.1 Enterprise 公开扫描额度

Enterprise 公开权利扫描 API 使用独立额度类型 `public_rights_scan_units`，并需要 API key、调用审计、网关限流和幂等额度流水。模型草案与 custody 边界见 `docs/Enterprise公开扫描API Key与额度账本模型草案.md`。

当前状态：

- 已完成 schema 草案、数据库迁移、内部 Storage 管理命令、受管理员 token 保护的内部后台入口、内部 CLI、quota balance 初始化逻辑、API key 内部列表 / 查询 / 暂停 / 撤销能力、内部操作审计细分、只读内部审计查询入口，以及桌面端 Enterprise 内部管理工作台。
- 已开放受 API key / scope / DB rate-limit / quota balance / quota ledger / API audit 保护的外部只读批量扫描路由：`POST /v1/enterprise/public-rights/batch`。
- 仍不开放外部客户 API key 管理、quota 管理、回填、撤销、替代、重签或媒体元数据写入路由；不得新增 `/v1/enterprise/api-keys` 或 `/v1/enterprise/quotas` 客户路由。
- 不把匿名批量 100 条上限包装成 Studio / Enterprise 可售额度。
- 不新增 `api_access=true` 自动开通逻辑。
- 已实现受管理员 token 保护的内部 API key 明文签发入口 `POST /internal/enterprise/api-key-issuances` 和 CLI `issue-api-key`：后端可信执行环境生成 256 bit 随机明文 key，使用 `HIDDENSHIELD_ENTERPRISE_API_KEY_HASH_SECRET` 与 secret version 计算 `hmac-sha256:v1:<secretVersion>:<digest>` 入库，明文只在签发响应或 CLI 输出中返回一次；列表、查询、审计、桌面内部页和错误响应不得返回明文或 `keyHash`。外部客户侧只开放 `POST /v1/enterprise/public-rights/batch` 只读扫描路由，已接 API key、scope、quota 自动扣减、API audit 和可信反向代理 hash-only IP / 指纹限流。生产形态仍要求 KMS / HSM 或等价 key custody、客户 SLA / 对账 / 支持流程签字，不开放客户自助 Enterprise API key 管理 UI。
- 已实现内部 key 轮换命令 `POST /internal/enterprise/api-keys/{apiKeyId}/rotate` 和 CLI `rotate-api-key`：复用同一套明文签发 / `keyHash` 入库流程生成新 active key，旧 key 立即进入 `paused`，并写入 `rotate_api_key` 审计；grace period 结束后的正式 `revoked` 仍走已有 revoke 入口或后续自动任务。
- 已实现内部过期轮换撤销巡检 `POST /internal/enterprise/api-key-rotations/revoke-expired` 和 CLI `revoke-expired-rotations`：按 `rotate_api_key` 审计 details 中的 `rotationDeadlineAt` 找出已到期且仍为 `paused` 的旧 key，自动调用 revoke 并写入 `revoke_api_key` 与 `revoke_expired_rotations` 审计；该巡检仍不接外部客户 API、不扣 quota、不读取或返回明文 / `keyHash`。
- 内部只读审计查询为 `GET /internal/enterprise/admin-audit-events`，支持按 operation / outcome / accountId / apiKeyId / occurredAt 范围过滤；该查询只服务内部管理和排障，不是外部客户审计 API。
- 桌面 Enterprise 内部管理页只调用 `/internal/enterprise/...`，支持 API key 元数据 create / list / get / pause / revoke、quota balance 初始化、审计筛选分页和当前页 JSON 导出；不调用 `/v1/enterprise/...`，也不生成或返回明文 API key。
- 外部 Enterprise API 网关合同、内部 dry-run helper、受管理员 token 保护的 `POST /internal/enterprise/gateway-dry-run`、CLI `dry-run-gateway` 和运行态 QA 门禁已固定：`EnterpriseGatewayAuthContext`、`EnterpriseGatewayRateLimitPolicy`、`EnterpriseGatewayQuotaChargePlan`、`EnterpriseGatewayAuditContract`、`EnterpriseGatewayReadOnlyScanContract`、`EnterpriseGatewayDryRunRequest`、`EnterpriseGatewayDryRunDecision`、`ENTERPRISE_GATEWAY_REQUIRED_STEPS`、`ENTERPRISE_GATEWAY_STABLE_ERROR_CODES` 和 `dry_run_enterprise_gateway_readonly_scan` 约束客户路由必须先经过 API key 鉴权、scope 授权、`api_access` 检查、限流、只读解析、quota ledger 和 API audit；内部 dry-run 入口只输入模拟 key / scope / quota / item 数并输出决策，只写 `dry_run_gateway` 管理审计，不写真实 quota ledger、不写外部 API audit、不扣真实额度。真实外部路由当前仅开放 `POST /v1/enterprise/public-rights/batch`，并由 `scripts/verify-enterprise-public-rights-runtime-qa.mjs` 覆盖缺 key 401、成功扣减、quota 不足拒绝和 `legalConclusion=false`。所有返回仍是训练许可声明和 registry 状态解释，不得表述为法律授权结论。

## 6. 一次性购买授权

Free 单份报告付费不进入 `features`，也不改变 `plan_code`。它属于一次性 purchase grant。

首期商品：

| product_code | 名称 | 价格 | 授权范围 |
| --- | --- | ---: | --- |
| `copyright_report_single` | 单份版权详细报告 | 19.9 元 / 份 | 单条 `vault_record_id` |
| `rights_evidence_pack_single` | 维权证据包 | 49.9 元 / 份 | 单条记录或单个案件 |

规则：

- `report_export=true` 的 Creator / Studio / Enterprise 可按订阅权益导出常规报告。
- Free 用户购买一次性报告后，只解锁对应记录或案件，不获得 `report_export=true`。
- 一次性购买必须由后端 payment session、provider webhook 或查单补偿写入授权。
- 退款、撤销或风控失败必须撤销授权。
- 授权记录不得包含原始媒体、加水印媒体、本地路径或保护副本路径。

建议授权模型：

- `report_purchase_grants`

关键字段：

- `grant_id`
- `account_id`
- `workspace_id`
- `creator_profile_id`
- `vault_record_id`
- `product_code`
- `price_cents`
- `currency`
- `payment_session_id`
- `provider`
- `provider_order_id`
- `status`
- `granted_at`
- `revoked_at`

## 8. Phase 8 支付扩展契约

Phase 8 在本文档的权益快照基础上增加支付与订阅状态闭环，详见 `docs/Phase 8 支付与订阅状态闭环设计.md`。

新增模型：

- `billing_customers`
- `subscriptions`
- `subscription_events`
- `entitlements`

规则：

- `subscription_events` 是支付 provider webhook 的幂等事件账本。
- 正式 `entitlements` 由后端 webhook 更新，客户端只读取权益快照。
- 首期可以继续把权益快照投影回账户表，保证桌面端和移动端既有同步链路不破坏。

Free 单份报告付费详见 `docs/Phase 8 Free单份报告付费设计.md`。该能力已纳入本版封版范围；UI 可展示购买入口，但真实支付通道未配置或未验收时必须展示“支付通道尚未完成配置”，不得伪造付款成功或授权成功。

自助订阅 payment session 当前只允许 `creator` 和 `studio`。`enterprise` 仍保留在权益模型和服务端授权模型中，但必须走受控客户开通流程，包括合同 / 客户确认、内部 quota 初始化、内部 API key 签发或轮换、网关 dry-run、生产运行态验收和审计留痕；不得创建 Enterprise 自助支付会话，也不得用 0 元自助订单绕过企业开通检查。

## 9. 客户端约束

- 桌面端和移动端都读取同一份 `entitlement.features`。
- 本地模式可缓存快照。
- 云端能力以服务端为最终裁判。
- 用户界面不暴露技术实现细节作为卖点。
- 单份报告授权以 `report_purchase_grants` 为准，客户端不能本地伪造授权。

Phase 1 先完成契约，不引入支付闭环，不引入订阅购买页面，不引入门禁逻辑。
