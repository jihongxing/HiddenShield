# 图片水印裁剪鲁棒性设计

## 背景

当前图片水印采用 DWT-DCT-SVD 写入 256 bit payload，并用 3 倍冗余做多数投票。它已经能稳定覆盖：

- PNG 重新编码
- JPEG Q90 / Q75
- 85% 缩放
- 常规写入 / 提取 / 拒绝重复写入

真实素材基准里剩余的失败项是 2% 边缘裁剪。根因不是 payload 本身损坏，而是裁剪会改变 DWT 的 LL 子带网格。原有算法从左上角按固定块序读取，裁剪后块序和原写入序列错位，常见表现是 payload magic 解码成全 `FF` 或其它无效头。

## 已验证但不采纳的方案

### 1. 块偏移扫描

做法：提取时尝试 `(0,0)`、`(1,0)`、`(0,1)`、`(1,1)` 等少量块偏移。

结论：能覆盖小尺寸单测，但不能稳定覆盖真实 1080x1080 样本的 2% 裁剪。真实裁剪每边约 21 像素，映射到 LL/DCT 块后不是简单的 1-2 个块偏移。

### 2. 中部锚点副本

做法：除主水印外，在图像中部额外写入一份 payload。

结论：仍不稳定。DWT 不是平移不变的，裁剪后整张图重新分解，原中部锚点不再对应同一批 LL 系数。

### 3. 直接把全图周期铺写作为唯一主路径

做法：把 payload 冗余位按周期铺满全部 LL 块，提取时扫描 768 个相位。

结论：方向上更接近裁剪问题，但不能替代主水印层。直接把它作为唯一主路径，会让老图兼容、普通提取性能和未命中耗时都变得不可控。

本轮最终采纳的是受控版本：主水印仍保留，周期铺写只作为密集恢复层；提取时仍先走主路径和 sync packet，失败后再进入有限相位扫描。

## 对标 blind_watermark 的结论

`guofei9987/blind_watermark` 采用 MIT License。它的图片水印核心同样是 DWT-DCT-SVD，但和 HiddenShield 原实现有几个关键差异：

- 它把水印 bit 按周期写入大量 DWT-DCT 分块，而不是只写前 256 bit 的固定区域。
- 它使用 YUV 三通道参与写入和提取，并按 bit 聚合多个块的结果。
- 它的慢速模式会把同一个 bit 同时写入 SVD 的 `s[0]` 和 `s[1]`，提取时再按主/副奇异值加权聚合。
- 它在 string/bit 提取时可使用阈值聚类。
- 它的很多裁剪演示并不是纯盲提取，而是通过原图或受攻击前图片做模板匹配，先估计裁剪区域并恢复画布，再执行提取。
- 它的旋转演示同样不是直接从旋转图提取，而是先做几何校正再执行提取；HiddenShield 产品侧只采纳 90/180/270 和镜像这组有限方向。

对 HiddenShield 的产品判断：

- 可以借鉴“周期铺写 + 聚合投票 + 双奇异值冗余”，作为图片写入后的密集恢复层，提高裁剪、局部损坏和常见重编码后的可验证性。
- 不应把带参考图、已知尺寸或已知攻击参数的恢复宣传成纯盲能力。它更适合放在版权库辅助的“深度检测”里，作为取证增强。
- 旋转攻击属于几何校正问题；默认提取只加入 90/180/270 和镜像等有限方向，超出这组离散变换的任意角度不作为产品承诺。
- 不直接复制 Python 实现；本项目使用 Rust 独立实现，并保留 MIT 项目致谢。

## 正式方案

采用“主水印 + sync packet 备份包 + 密集恢复层”：

1. 主水印层保持现有顺序布局。
   - 继续写入前 `PAYLOAD_BITS * REDUNDANCY` 个块。
   - 保持老图可提取。
   - 保持常规提取性能。

2. sync packet 备份包。
   - payload 业务内容仍为 32 字节。
   - 外层增加 4 字节同步前导码和 2 字节 checksum。
   - 新写入图片在主水印后追加最多 6 份 sync packet 副本，并在左侧、近左侧、右侧锚点间分布。
   - 提取时只有主路径和多尺度候选都失败后，才进入有限 sync packet 搜索。
   - 前导码命中后允许最多 2 bit 有界纠错，纠错结果必须同时通过 sync checksum 和 payload HMAC。

3. 密集恢复层。
   - payload 冗余 bit 按 768 bit 周期铺满 LL 分块。
   - 前 768 个块与主水印层兼容，避免破坏旧提取逻辑。
   - 提取时扫描有限相位，并按 bit 聚合投票。
   - 该层借鉴 `blind_watermark` 的周期铺写思想，但使用 HiddenShield 自有 payload、HMAC 校验和 Rust 实现。

4. 双奇异值冗余。
   - 新写入图片在每个 DCT-SVD 分块中同时写入 `sigma[0]` 和 `sigma[1]`。
   - `sigma[0]` 仍作为主承载层，保证旧水印和主流程兼容。
   - `sigma[1]` 作为副承载层，使用较低量化强度，并在提取时按 3:1 加权参与判决。
   - 该策略借鉴 `blind_watermark` 慢速模式的 SVD 双奇异值思想，但量化、payload 和提取评分均为 HiddenShield 独立实现。

5. 参考图辅助深度检测。
   - 当版权库存在受保护副本时，可先匹配疑似裁剪图在参考图中的位置。
   - 匹配成功后恢复到参考画布，再走普通提取和密集恢复。
   - 该路径不进入默认盲提取承诺，不能作为“任意裁剪/任意缩放可恢复”的产品指标，后续应在 UI 上作为“基于版权库记录的深度检测”展示。

6. 多尺度候选提取。
   - 只使用疑似文件自身做有限尺度候选，不假设原图尺寸、裁剪坐标或攻击参数。
   - 覆盖常见 85% 缩放的盲检测回补。
   - 控制候选数量，避免未命中时无限扫描。

7. 音频鲁棒性增强。
   - 采用相对频段能量写入。
   - 保留 legacy QIM 提取回退。
   - 支持 22.05kHz / 44.1kHz 采样率场景和 WAV 重采样回退。

## 关键约束

- 默认提取必须有上限，不能因为未命中而扫完整张图。
- 默认盲检测只能依赖疑似文件本身，不能假设知道原图、原尺寸、裁剪参数或旋转角度。
- 写入不能显著增加图片处理耗时。
- 任何恢复层都不能破坏主水印层。
- 老版本写出的图片仍必须可提取。
- 未加水印图片的“写入前重复检测”不能被慢路径拖垮。

## 版本策略

当前 payload 仍是 32 字节，不新增字段，不改变 `watermark_uid` 计算，也不影响桌面端和移动端协议。

sync packet 和密集恢复层只改变图片水印外层编码，不改变业务 payload 和版权库字段。旧版图片仍可通过主水印层提取；新版图片优先走主水印层，失败后再走 sync packet 和密集恢复层。

产品判断：

- 图片/音频单文件写入可以接受，但批量处理必须走后台队列、进度展示和可取消任务。
- 图片正常提取和 2% 裁剪提取已进入可接受范围。
- 参考辅助裁剪检测耗时更高，并且依赖版权库记录，应作为显式“深度检测”或后台取证任务，不计入默认盲检测承诺。
- 90/180/270、水平镜像和垂直镜像已进入默认路径，并且 17/17 稳定通过。
- 亮度 110% 已从 11/17 提升到 17/17，说明亮度变化应继续按盲检测增强处理，而不是依赖已知攻击参数恢复。
- 85% 缩放已从 15/17 提升到 17/17，修复方式是让有限尺度候选进入完整恢复层，不依赖原图尺寸或已知缩放参数。
- 纯盲 2% 轻裁剪已从 16/17 提升到 17/17，修复方式是增加 2% 裁剪后的相对补边比例 `0.0208`，不扫描任意裁剪参数。
- sync packet 横向分布已把 15% 中心竖向遮挡从 15/17 提升到 16/17。
- sync packet 2 bit 有界纠错继续把 15% 中心竖向遮挡提升到 17/17，17 张真实图片默认盲检测矩阵达到 306/306。
- 批量处理仍需要后台队列、并发上限、进度展示和可取消任务。

下一步性能优化方向：

1. 把“深度检测”接入桌面端和移动端验证页，但默认检测仍保持快速路径。
2. 为参考辅助检测展示匹配分数、覆盖比例和水印 UID，避免只凭单一结果断言。
3. 将任意角度旋转实验冻结为非产品研究项，不再继续投入默认检测路径。
4. 批量写入增加并发上限，默认按 CPU 核心数保守并行。
