# HiddenShield 感知质量发布门禁设计

更新时间：2026-06-30

本文用于补齐 HiddenShield 在图片、音频、L1 视频音轨和 L3 视频画面 staged 能力上的感知质量门禁。它回答一个产品发布问题：保护副本写入后不仅要能读回水印，还要证明对用户的观感 / 听感影响低于可接受阈值。

## 1. 设计结论

先建立感知质量发布门禁，再决定是否把 `Forensic` 和 `Balanced` 两档作为用户可选策略。

当前 `watermark-core` 已存在 `WatermarkStrength::Forensic` 和 `WatermarkStrength::Balanced`，但这只代表核心算法有两组强度参数，不代表产品层已经可以承诺“用户可自由选择强度”。发布策略应按下面顺序推进：

1. `Forensic` 继续作为默认内部策略。
2. `Balanced` 只作为质量候选策略进入测试矩阵。
3. 只有某一策略同时通过“可提取性门禁”和“感知质量门禁”，才允许进入用户可见策略列表。
4. 如果某一媒体类型未通过门禁，该媒体类型不得展示对应策略选项，即使其他媒体类型已经通过。

## 2. 范围

纳入门禁：

- 图片盲水印：PNG / JPEG / WebP 输入，按正式保护副本输出路径比较。
- 音频盲水印：WAV 以及 MP3 / FLAC / OGG / M4A 归一化后的正式写入路径。
- L1 视频音轨水印：先抽取音轨，按音频门禁评价水印对音轨的影响。
- L3 视频画面盲水印：仅限 `watermark-core` / Tauri staged 测试层，用 VMAF 作为画面质量指标之一；不改变当前 L3 不对用户开放的边界。

不纳入本文：

- 修改 `Watermark Payload Protocol V2` 或 `PAYLOAD_BYTES = 119`。
- 新增 payload 字段、训练许可字段或公开权利信号字段。
- 调整水印算法参数本身。
- 承诺“无损”“零影响”“已证明不可感知”。

## 3. 门禁原则

感知质量门禁必须和可提取性门禁同时成立：

| 结果 | 发布判定 |
| --- | --- |
| 可提取通过，感知质量通过 | 可以进入候选发布 |
| 可提取通过，感知质量失败 | 阻断发布；说明水印能读回但扰动过大 |
| 可提取失败，感知质量通过 | 阻断发布；说明扰动小但保护能力不足 |
| 可提取失败，感知质量失败 | 阻断发布；算法或参数不可发布 |

比较对象必须使用同一条正式输出链路：

- 无损输出：原始解码结果 vs 保护副本解码结果。
- 有损输出：同格式、同编码参数的“未写入水印控制副本” vs “保护副本”，避免把格式转换损失误判为水印损失。
- 音频容器：先归一化到同采样率、同声道、同 bit depth / float 表示后比较。
- L1 视频音轨：抽取成品视频音轨后，与同转封装 / 同编码设置的控制音轨比较。
- L3 视频画面：用同编码 profile、码率、分辨率、帧率的控制视频和写入视频比较。

## 4. 图片质量门禁

图片使用 PSNR 和 SSIM 作为 release-blocking 指标，差异热力图、最大像素差、局部块差异作为诊断指标。

| 策略 | 最低 PSNR | 最低 SSIM | 阻断规则 |
| --- | ---: | ---: | --- |
| Balanced 候选 | >= 42 dB | >= 0.995 | 任一生产样本低于阈值即阻断 |
| Forensic 默认 | >= 38 dB | >= 0.990 | 任一生产样本低于阈值即阻断 |

诊断指标：

- 记录最大通道差异、平均绝对误差 MAE、95 分位像素差。
- 生成差异热力图，但热力图不单独作为阻断项。
- 对文字截图、纯色插画、低纹理渐变图应单独分组，因为这些样本比自然照片更容易暴露扰动。

图片样本池最低要求：

| 分组 | 最低数量 | 目的 |
| --- | ---: | --- |
| 人像 / 自然照片 | 10 | 覆盖当前真实照片主场景 |
| 低纹理渐变 / 纯色背景 | 6 | 捕捉平滑区域可见噪点 |
| 插画 / 线稿 / 海报 | 6 | 捕捉边缘和色块扰动 |
| 文字截图 / UI 截图 | 6 | 捕捉文字边缘、细线和压缩伪影 |
| 暗光 / 高 ISO / 高细节 | 6 | 捕捉噪声区和高频区风险 |
| 最小尺寸边界样本 | 4 | 验证接近最低容量时的质量风险 |

## 5. 音频质量门禁

音频使用 SNR、Integrated LUFS 差异、峰值差异和新增削波作为 release-blocking 指标。主观试听或 ABX 作为发布前人工抽检，不替代自动门禁。

| 策略 | 最低 SNR | Integrated LUFS 差异 | 峰值差异 | 削波 |
| --- | ---: | ---: | ---: | --- |
| Balanced 候选 | >= 50 dB | <= 0.3 LU | <= 0.5 dB | 不允许新增 clipping sample |
| Forensic 默认 | >= 44 dB | <= 0.5 LU | <= 0.8 dB | 不允许新增 clipping sample |

补充规则：

- 静音段不参与整体 SNR 的主判定，但必须记录静音段噪声底抬升。
- 如果原始音频已经存在削波，只允许记录原始削波，不允许保护副本新增削波点。
- 30 秒以下音频不进入生产承诺门禁，只作为观察项。
- L1 视频音轨水印使用同一套音频门禁；必须比较成品视频抽取音轨，而不是只比较中间 WAV。

音频样本池最低要求：

| 分组 | 最低数量 | 目的 |
| --- | ---: | --- |
| 人声 / 播客 / 旁白 | 8 | 捕捉语音清晰度和齿音风险 |
| 流行音乐 / 高动态音乐 | 8 | 捕捉宽频内容和响度变化 |
| 安静 / 稀疏 / 古典片段 | 6 | 捕捉低能量段噪声抬升 |
| 噪声环境 / 现场录音 | 6 | 捕捉复杂噪声底下的误差 |
| 单声道 / 立体声 | 各 4 | 覆盖声道处理边界 |
| MP3 / FLAC / OGG / M4A 输入 | 各 4 | 覆盖正式归一化路径 |

## 6. 视频质量门禁

视频分为两类：

- L1 视频音轨水印：只评价音轨，使用第 5 节音频门禁。
- L3 视频画面盲水印：当前仍是 staged / 内部测试能力，使用 VMAF、视频 PSNR、视频 SSIM 做内部 release 研究门禁，不进入用户承诺。

L3 staged 画面质量阈值：

| 策略 | VMAF 下降 | 最低视频 PSNR | 最低视频 SSIM | 发布边界 |
| --- | ---: | ---: | ---: | --- |
| Balanced 候选 | <= 1.0 | >= 40 dB | >= 0.995 | 仅可进入内部候选 |
| Forensic 默认 | <= 2.0 | >= 37 dB | >= 0.990 | 仅可进入内部候选 |

补充规则：

- VMAF 使用控制视频 vs 写入视频比较，不能直接拿原始视频和转码后保护副本比较。
- 横屏、竖屏、3:4、低纹理、高细节、字幕密集和平台二压样本要分组统计。
- 任一视频策略即使通过 VMAF，也必须继续满足 L3 自检 confidence、payload 一致性和 release 样本池阈值；VMAF 只证明画质，不证明水印可用。
- 在 L3 当前边界未解除前，VMAF 结果不得进入销售、订阅权益、用户报告或云端任务 SLA。

## 7. Forensic / Balanced 用户可选策略判定

策略暴露采用逐媒体类型准入：

| 媒体类型 | 当前建议 | 用户可选前置条件 |
| --- | --- | --- |
| 图片 | 默认继续使用 Forensic；Balanced 进入质量候选矩阵 | 图片可提取 release 门禁 + 图片 PSNR / SSIM 门禁双通过 |
| 音频 | 默认继续使用 Forensic；Balanced 进入质量候选矩阵 | 音频可提取 release 门禁 + SNR / LUFS / 峰值门禁双通过 |
| L1 视频音轨 | 跟随音频策略，不单独设计强度档 | 成品视频抽取音轨后通过音频门禁 |
| L3 视频画面 | 不进入用户可选策略 | L3 当前仍未开放；即使内部通过 VMAF，也不能开放 UI |

用户可见命名建议等门禁完成后再决定。当前不建议在 UI 中直接展示 “Forensic / Balanced”，因为这两个词是工程强度名，不一定是用户理解的产品语言。更稳妥的产品命名可以是“标准保护”和“低扰动保护”，但必须等门禁结果支持后再定。

## 8. 自动化报告结构

建议新增独立报告，不混入现有鲁棒性报告：

```text
watermark-core/target/perceptual-quality-gate/run-<timestamp>/
  report.md
  report.json
  images/
    <sample-id>/
      control.png
      protected.png
      diff-heatmap.png
  audio/
    <sample-id>/
      control.wav
      protected.wav
      loudness.json
  video/
    <sample-id>/
      control.mp4
      protected.mp4
      vmaf.json
```

`report.json` 最少字段：

| 字段 | 说明 |
| --- | --- |
| `mediaType` | `image` / `audio` / `video_audio_track` / `video_visual_staged` |
| `strategy` | `forensic` / `balanced` |
| `sourceProfile` | 样本分组 |
| `extractPassed` | 写入后是否读回同一 payload |
| `qualityPassed` | 感知质量是否过线 |
| `releaseBlockingReason` | `none` / `extract_failed` / `psnr_below_threshold` / `ssim_below_threshold` / `snr_below_threshold` / `lufs_delta_above_threshold` / `peak_delta_above_threshold` / `new_clipping` / `vmaf_delta_above_threshold` |
| `metrics` | 各媒体类型的指标对象 |

音频 `metrics.debug` 诊断字段：

| 字段 | 说明 |
| --- | --- |
| `shortTimeRms.min/mean/max` | 按 `watermark-core` V3 音频帧统计的短时 RMS |
| `lowEnergyFrameRatio` | 低能量帧比例 |
| `transientFrameRatio` | 瞬态帧比例 |
| `noiseLikeFrameRatio` | 噪声型频谱帧比例 |
| `embeddingStrength.minContrast/meanContrast/maxContrast` | 本轮 V3 recovery lane 使用的自适应目标对比度分布 |
| `embeddingStrength.modifiedPairRatio` | 相对频带 pair 中需要最小改写的比例 |
| `noiseFloorSparseRecovery` | 是否触发稳定噪声底专用的 V3 recovery lane-majority 稀疏写入实验策略 |
| `extractionConfidence` | protected 样本相对 expected V3 recovery packet 的 bit 级匹配置信度 |

## 9. 当前实现状态

当前已实现开发回归级 V3 fast gate：

```powershell
npm run watermark:quality-gate:fast
npm run watermark:quality-gate:release
npm run watermark:quality-gate:full
npm run watermark:quality-gate:contract
```

`watermark:quality-gate:fast` 由 `watermark-core/src/bin/v3_quality_gate.rs` 生成报告，当前覆盖：

- 图片 V3 roundtrip：PSNR、SSIM、roundtrip 耗时，当前 fast 阈值为 `IMAGE_MIN_PSNR = 33.0`、`IMAGE_MIN_SSIM = 0.985`、`IMAGE_MAX_ROUNDTRIP_MS = 20000`。
- 音频 V3 roundtrip：SNR、Integrated LUFS 差异、峰值差异、新增 clipping，当前 fast 阈值为 SNR `>= 35 dB`、LUFS 差异 `<= 1.5 LU`、峰值差异 `<= 0.08`。
- 视频 VMAF：当前只记录跳过原因；正式 VMAF 需要 FFmpeg + libvmaf，并且 L3 视频画面仍属于 staged / 内部测试边界。

当前 fast gate 用于本地开发和回归，不替代本文件第 4 至第 6 节定义的 release/full 样本池。尤其图片 V3 小图 roundtrip 已有性能增强和 fast 指标，但还不能据此宣传“不可见”“零影响”或开放 `Forensic` / `Balanced` 用户可选策略。

当前已新增 full gate 入口：

```powershell
npm run watermark:quality-gate:full
```

该命令复用 `watermark-core/src/bin/v3_quality_release_gate.rs --scope full`，输出 `watermark-core/target/perceptual-quality-full-gate/run-<runId>/quality-full-gate.json` 和 `quality-full-gate.md`，并生成 `abx/*.csv` 人工盲测模板。full gate 当前扩展了图片、音频和 L1 视频音轨的确定性风险样本池，使用更接近 Forensic 发布口径的阈值；L2 视频指纹存证在报告中固定为 `videoFingerprintNotary.status=not_applicable_no_media_mutation`，因为它不注入或改写媒体；L3 视频画面固定为 `videoVisualStaged`，链接 `watermark:l3-video-visual-release-gate` 和未来 VMAF / video PSNR / video SSIM / ABX 模板，不能进入用户“无感”承诺。

## 10. 发布门禁命令建议

后续可以新增三层命令：

```powershell
npm run watermark:quality-gate:fast
npm run watermark:quality-gate:release
npm run watermark:quality-gate:full
```

建议口径：

- `fast`：少量 fixture，用于开发本地回归，不作为发布证据。
- `release`：覆盖图片 / 音频 / L1 视频音轨生产样本池，作为当前发布阻断门禁。
- `full`：扩展图片 / 音频 / L1 视频音轨风险样本池并生成 ABX 模板；L3 staged 视频 VMAF 仍只记录为内部候选，不作为当前用户发布阻断项。

## 11. 当前项目边界

本文建立的是门禁设计，不改变当前能力承诺：

- 现阶段仍只能承诺图片 / 音频 / L1 视频音轨保护副本可写入、可验证、可跨端互读。
- 尚不能承诺 HiddenShield 水印“完全无损”“零影响”或“已证明不可感知”。
- 尚不能把 Balanced / Forensic 两档展示为用户可选策略。
- L3 视频画面盲水印即使补充 VMAF 指标，也仍是 staged / 内部测试能力。
