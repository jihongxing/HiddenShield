# HiddenShield 商业化落地阶段收尾

本文档用于收口 HiddenShield 当前商业化落地阶段，并明确后续工作重心切回桌面端与移动端的核心能力一致性。

## 1. 阶段结论

商业化落地当前达到“阶段性完成”状态。

这里的“阶段性完成”含义是：

- 商业模式、套餐分层和权益边界已经固化。
- Free / Creator / Studio / Enterprise 术语已在桌面端、移动端、后端和文档中统一。
- 本地批量、云同步、正式报告、L2 视频指纹存证、支付入口、权益刷新和商业指标看板均已具备代码或契约支撑。
- 双端商业化页面与门禁已完成阶段性 QA。
- 商业化合同脚本和 CI 门禁已经建立，后续接口变更不应绕过这些检查。

这里的“阶段性完成”不等于正式收费上线。

正式收费上线前仍需要外部或生产环境准备：

- 微信支付真实商户沙箱 / 生产联调。
- 隐私政策、用户协议、支付订阅条款的法律顾问审阅。
- 生产环境配置 `HIDDENSHIELD_COMMERCIAL_METRICS_ADMIN_TOKEN`。
- 生产网络侧限制商业指标后台访问来源。
- 运行态 Tauri / 移动端真机的最终人工验收。

## 2. 已完成能力边界

### 商业化基础

- 商业化执行总线：`docs/商业化落地Roadmap.md`。
- 商业化契约：`docs/商业化契约与权益模型.md`。
- Free / Creator / Studio / Enterprise 套餐和权益口径。
- 商业化任务必须回写 Roadmap 的 Agent 约束。

### 权益与付费路径

- 账户继续使用 / 登录注册合一。
- 账户级 entitlement 快照。
- 双端订阅入口。
- 微信支付 provider 抽象与首期微信支付 APIv3 方向。
- payment session、支付状态查询、手动确认支付、后台补偿任务和 entitlement 恢复链路。
- 客户端不保存支付密钥，不自行开通正式权益。

### Creator 权益

- 本地批量处理作为 Creator 订阅权益。
- 云同步作为 Creator 订阅权益。
- 正式报告导出作为 Creator 订阅权益。
- L2 视频指纹存证作为 Creator / Studio 阶段能力。

### Studio / Enterprise 预留

- Studio 团队空间、席位、共享版权库和审计模型已预留。
- Enterprise 保持咨询 / 定制入口，不伪装为直接购买。

### Phase 9 上线准备

- 商业化上线验收 Checklist。
- 双端商业化 QA 记录。
- 隐私政策草案。
- 用户协议草案。
- 支付与订阅条款草案。
- 商业指标看板设计。
- `/v1/commercial/metrics/overview` 聚合接口。
- 管理员 token 鉴权与 `admin_audit_events` 访问审计。

## 3. 不再继续展开的内容

当前阶段不继续无休止打磨以下商业化细节：

- 更复杂的 BI 看板。
- 更多支付 provider。
- Studio 团队真实协作管理。
- Enterprise 销售流程。
- L3 云端视频画面盲水印。
- 点数包、优惠券、发票、自动续费细则。

这些内容保留在商业化 Roadmap 中，但不作为下一阶段默认推进目标。

## 4. 下一阶段主线

下一阶段主线切换为：

**桌面端与移动端核心能力一致性。**

目标是让用户在桌面端和移动端看到的是同一个产品，而不是两个能力不同的工具。

下一阶段优先关注：

- 图片写入、提取、完成态、验证态一致。
- 音频写入、提取、30 秒规则、格式支持和错误提示一致。
- 版权库字段、详情页、筛选、报告入口一致。
- 本地批量队列和单文件处理口径一致。
- 云同步数据模型、冲突处理、失败重试和隐私边界一致。
- L2 视频指纹存证在双端的展示和报告字段一致。
- 双端术语、空状态、失败态和操作路径一致。

具体执行主线见 `docs/双端能力一致性Roadmap.md`。
