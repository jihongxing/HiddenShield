# HiddenShield 用户体系与登录注册体系规划

更新时间：2026-06-27

本文档用于规划 HiddenShield 正式用户体系。当前后端版权编号服务已经进入双端写入流水线，用户体系需要从“研发期继续账户”升级为“正式注册、登录、会话、设备、创作者档案、工作区、权益和版权编号登记”一体化链路。

## 1. 目标

- 不登录也能继续本地写入、验证和查看本地版权库。
- 登录后，用户获得统一账户、默认个人空间、设备登记、创作者档案、权益快照、版权编号在线签发、云同步和报告购买能力。
- 已登录且权益为 Creator / Studio / Enterprise 的用户，双端必须自动启用正式云同步：桌面端和移动端版权库记录自动入队、自动上传到云端、自动拉取另一端变更，并在云端保存版权库内容的同步白名单字段。
- 后端版权 ID 服务必须绑定认证后的 `accountId + workspaceId + deviceId + creatorProfileId`，不能只把版权编号当成匿名接口。
- 桌面端和移动端使用同一套注册 / 登录 / 会话 / 退出 / 换机恢复模型。
- 用户体系为未来 Creator 订阅、Free 单份报告、Studio 团队空间、Enterprise API 和维权服务打基础。

## 2. 当前状态

已经具备：

- 后端正式 Auth API：`POST /v1/auth/challenges`、`POST /v1/auth/sessions`、`POST /v1/auth/refresh`、`POST /v1/auth/logout`、`GET /v1/me` 已落地；`auth/continue` 仅保留为开发 / 迁移 alias，不再作为双端主入口。
- 后端 `watermark-ids reserve / confirm / reconcile / reissue`：已被桌面端和移动端图片 / 音频写入流水线在线优先调用。
- 桌面端和移动端本地保存 `accountId`、`workspaceId`、`deviceId`、`creatorProfileId`、`accessToken`、`refreshToken` 和权益快照。
- 云同步、报告购买、版权编号登记、订阅权益已经能够读取同一组账户上下文；Creator / Studio / Enterprise 在正式 sessions / me / refresh 返回 `auto_cloud_vault` 或用户暂停后的 `manual_local_only`。

当前不足：

- `auth/challenges` 已支持可配置验证码投递 webhook；未配置 `HIDDENSHIELD_AUTH_OTP_DELIVERY_ENDPOINT` 时仍使用 fixture `000000` 供本地 / 合同测试，配置 webhook 后合同测试已验证服务端不向客户端返回明文验证码并能使用投递验证码登录。真实短信 / 邮件供应商生产参数、模板审核、送达率和失败告警仍待上线联调。
- 当前新密码写入已使用 Argon2id，旧研发期 salted SHA-256 仅在成功登录后迁移；后续仍需补充生产参数审计、告警和会话风控。
- 设备列表、设备重命名和撤销其他设备会话已形成双端基础 UI；找回登录、换机恢复、批量会话撤销、设备风险审计仍未完成。
- 桌面端和移动端登录 UI 已升级为验证码 / 密码登录；设备管理 / 会话撤销基础 UI 已接入设置页，后续仍需补换机恢复、批量撤销和真实短信 / 邮件供应商生产联调。
- 后端版权 ID 服务已经接入，但用户对“为什么要登录、登录后编号如何登记、离线编号如何补登记”的产品心智还需要统一。
- 后续文档、UI 和 Roadmap 需要继续收口到“已登录 Creator 自动云同步版权库”，用户可暂停自动同步，但默认不要求手动开启。

## 3. 第一性原则

HiddenShield 用户体系不是为了阻断本地使用，而是为了把正式保护副本和后端登记、同步、报告、购买、团队、维权服务连接起来。

原则：

- 本地优先：未登录用户仍可完成图片 / 音频本地保护副本写入和验证。
- 在线增益：登录后获得后端签发版权编号、登记确认、云同步、跨设备恢复、报告购买和权益同步。
- Creator 自动同步：已登录且 `entitlement.features.cloud_sync=true` 时，桌面端和移动端默认进入 `SyncMode.cloud`，自动同步双端版权库，而不是只展示“可开启”。
- 隐私最小化：登录不改变“不上传原始媒体、加水印媒体、本地路径”的默认边界。
- 账户归属清晰：后端登记记录必须能回答“属于哪个账户、哪个工作区、哪个创作者档案、哪台设备”。
- 设备可撤销：丢失设备或换机时，可撤销旧设备 refresh token，不影响本地已存在数据。
- 创作者档案独立于账号登录名：账号可以是邮箱 / 手机，水印归属展示使用创作者档案。

## 4. 产品模型

### 4.1 本地模式

默认模式。

用户可用：

- 本地图片 / 音频水印写入。
- 本地验证。
- 本地版权库。
- 本地保护副本导出。
- 离线高熵版权编号。

用户不可用：

- 后端编号确认。
- 云同步。
- 换机恢复。
- Creator / Studio / Enterprise 权益同步。
- Free 单份报告真实购买授权核销。

用户文案：

```text
可继续本地使用。登录后可获得后端版权编号登记、跨设备同步和报告购买能力。
```

### 4.2 登录模式

登录后，客户端获得：

- `accountId`
- `workspaceId`
- `deviceId`
- `creatorProfileId`
- access token
- refresh token
- entitlement snapshot

登录后主线：

```text
选择作品
  -> 写入前 reserve watermark id
  -> watermark-core 构造 V2 payload
  -> 生成保护副本
  -> 写入后 confirm
  -> 版权库保存 server_confirmed / offline_confirmed / pending_registration
  -> Creator / Studio / Enterprise 自动云同步版权库内容到云端
  -> 另一端自动拉取并合并版权库变更
```

自动云同步触发条件：

- 用户已登录，且 access token / refresh token 可用。
- 当前账户权益快照中 `cloud_sync=true`。
- 当前设备未被撤销。
- 当前工作区有效，且用户对该 workspace 有写权限。

自动云同步行为：

- 登录成功后立即拉取云端版权库变更，并把本机待同步记录入队上传。
- 每次新增写入记录、验证记录、报告授权状态、版权编号登记状态变化后自动入队。
- 应用启动、恢复前台、网络从不可用恢复、token refresh 成功后自动 flush 队列并 pull 变更。
- 自动同步失败不阻断本地写入，记录进入重试队列并展示同步健康状态。
- 用户可在设置中“暂停自动云同步”，但 Creator 默认状态是开启；暂停只影响自动发送，不删除本地版权库和本地队列。

云端保存的“版权库内容”定义为同步白名单字段：

- 版权记录基础字段：标题 / 文件名、媒体类型、创建时间、创作者档案、版权编号、版本次数、父编号、重写说明。
- 作品和保护副本摘要：原作品 SHA-256 摘要、保护副本名称、保护副本 SHA-256 摘要、输出策略。
- 写入后验证字段：验证状态、验证说明、验证时间。
- 版权编号登记字段：签发模式、登记状态、登记收据、payload protocol、payload bytes、payload auth status。
- 作品声明字段：作品来源、训练许可、创作方式、人工编辑程度、真实性声明、自定义版权声明。
- 报告和购买授权字段：报告购买授权摘要、退款撤销状态、正式报告可导出状态。
- L2 视频指纹存证字段：notary id、fingerprint root、bundle sha256、采样策略等不可逆摘要。

默认不同步：

- 原始媒体文件。
- 加水印后的保护副本文件。
- 本地文件路径。
- 本地 bundle 路径。
- 可还原媒体内容的完整数据。
- 创作者 seed 明文。

### 4.3 注册和登录入口

入口统一称为：

```text
登录 HiddenShield / 仅本地使用
```

正式流程拆成清晰状态：

- 新用户：输入邮箱 / 手机 -> 验证码 -> 设置创作者档案 -> 创建个人空间 -> 登记本设备。
- 老用户：输入邮箱 / 手机 -> 验证码或密码 -> 选择 / 确认创作者档案 -> 登记本设备。
- 已登录用户：显示账户、空间、设备、权益和同步状态。
- 后端不可用：允许继续本地模式，不阻断写入。
- 已登录 Creator：不再要求用户手动开启云同步，默认显示“版权库正在自动同步”；若用户暂停，则显示“自动同步已暂停，本地记录会保留在待同步队列”。

## 5. 账号身份模型

### 5.1 Account

平台账户，是后端登记、权益、支付、团队和审计的顶层主体。

建议字段：

- `id`
- `primary_email`
- `primary_phone`
- `display_name`
- `status`: `active` / `locked` / `deleted`
- `created_at`
- `updated_at`

规则：

- 邮箱和手机号至少绑定一种。
- 不把创作者展示名等同于登录账号。
- 删除账户前必须处理订阅、报告授权、团队工作区和登记记录保留策略。

### 5.2 Credential

登录凭据，独立于账户基础资料。

建议表：

- `account_credentials`

字段：

- `credential_id`
- `account_id`
- `type`: `email_otp` / `phone_otp` / `password` / `wechat` / `apple`
- `identifier_hash`
- `password_hash`
- `password_hash_algo`
- `verified_at`
- `last_used_at`
- `created_at`

正式要求：

- 密码 hash 使用 Argon2id / bcrypt / scrypt，不使用普通 SHA-256。
- 验证码只保存 hash 和过期时间，不保存明文。
- 登录失败、验证码发送和校验必须限流。

### 5.3 Workspace

工作区是版权库、报告、团队和权益作用域。

首期：

- 每个账户默认一个个人空间。

后续：

- Studio / Enterprise 支持团队空间。
- 一个账户可属于多个 workspace。

建议字段：

- `workspace_id`
- `owner_account_id`
- `name`
- `type`: `personal` / `team`
- `cloud_vault_enabled`
- `cloud_vault_auto_sync_policy`: `auto` / `paused_by_user` / `disabled_by_entitlement`
- `created_at`
- `updated_at`

### 5.4 Workspace Member

团队阶段需要成员模型。

建议字段：

- `workspace_id`
- `account_id`
- `role`: `owner` / `admin` / `creator` / `viewer` / `billing_admin`
- `status`
- `joined_at`

首期个人空间可以不展示成员管理，但数据模型应预留。

### 5.5 Device

每台桌面端或移动端安装都是独立设备。

建议字段：

- `device_id`
- `account_id`
- `workspace_id`
- `client_device_id`
- `name`
- `platform`
- `app_version`
- `public_key`
- `trusted`
- `last_seen_at`
- `revoked_at`
- `auto_sync_enabled`
- `last_cloud_vault_sync_at`
- `created_at`

规则：

- access token 绑定账户和设备。
- refresh token 绑定设备，可单设备撤销。
- 设备撤销后不能继续使用云同步、版权 ID reserve / confirm / reconcile。
- 本地数据不因退出或撤销自动删除，除非用户明确清除。
- Creator 设备登录成功后默认 `auto_sync_enabled=true`；Free 设备登录成功后可保留账户和编号登记能力，但正式双端版权库自动同步受 `cloud_sync=false` 阻断。

### 5.6 Creator Profile

创作者档案是水印归属和版权记录展示主体。

建议字段：

- `creator_profile_id`
- `account_id`
- `workspace_id`
- `display_name`
- `creator_seed_ref`
- `seed_envelope_version`
- `is_default`
- `status`
- `created_at`
- `updated_at`

规则：

- 首次登录时把本机创作者身份合并为默认创作者档案。
- 允许未来一个账户拥有多个创作者档案，但首期只开放默认档案。
- 水印 payload 不写入账号明文或创作者明文，只写入 creator binding hash。

### 5.7 Session

会话用于访问云 API。

建议字段：

- `session_id`
- `account_id`
- `device_id`
- `access_token_hash`
- `refresh_token_hash`
- `refresh_token_family_id`
- `expires_at`
- `refresh_expires_at`
- `revoked_at`
- `created_at`
- `last_used_at`

规则：

- access token 短期有效，建议 15 到 60 分钟。
- refresh token 长期但必须轮换，建议 30 到 90 天。
- 每次 refresh 生成新的 refresh token，旧 token 立即失效。
- 检测到旧 refresh token 被复用时，撤销同 token family 的会话。

## 6. 正式 API 规划

### Phase U-1：验证码 / 密码登录基础

```http
POST /v1/auth/challenges
POST /v1/auth/sessions
POST /v1/auth/refresh
POST /v1/auth/logout
GET  /v1/me
PATCH /v1/me/sync-preferences
```

`POST /v1/auth/challenges`

用途：发送邮箱 / 手机验证码。

输入：

- `identifier`
- `purpose`: `register_or_login` / `login` / `bind_identifier` / `reset_password`
- `clientDeviceId`
- `captchaToken` 可选

输出：

- `challengeId`
- `deliveryChannel`
- `expiresAt`
- 中性提示文案，不直接泄漏账号是否存在。

`POST /v1/auth/sessions`

用途：完成注册或登录，创建会话。

输入：

- `identifier`
- `challengeId`
- `verificationCode` 或 `password`
- `device`
- `localCreatorProfile`

输出：

- `accessToken`
- `refreshToken`
- `account`
- `workspace`
- `device`
- `creatorProfile`
- `entitlement`
- `pendingLocalMergeAdvice`
- `syncPolicy`: `auto_cloud_vault` / `manual_local_only` / `blocked_by_entitlement`
- `cloudVaultCursor`

`POST /v1/auth/refresh`

用途：刷新 access token，并轮换 refresh token。

输入：

- `refreshToken`
- `deviceId`

输出：

- 新 `accessToken`
- 新 `refreshToken`
- 最新权益快照。

`POST /v1/auth/logout`

用途：退出当前设备。

输入：

- `refreshToken`
- `deviceId`

行为：

- 撤销当前设备 refresh token。
- 客户端保留本地版权库和本地同步队列。

`GET /v1/me`

用途：返回当前账户、工作区、设备、创作者档案和权益快照。

`PATCH /v1/me/sync-preferences`

用途：暂停或恢复当前设备的自动云同步。

输入：

- `autoSyncEnabled`
- `reason`: `user_paused` / `user_resumed`

规则：

- 只有 `cloud_sync=true` 的账户可恢复自动云同步。
- 暂停同步不删除云端版权库内容，不删除本地版权库，不清空本地队列。
- 恢复同步后先 pull 再 flush，避免覆盖另一端新记录。

### Phase U-2：设备和创作者档案管理

```http
GET    /v1/devices
PATCH  /v1/devices/{deviceId}
DELETE /v1/devices/{deviceId}
GET    /v1/creator-profiles
POST   /v1/creator-profiles
PATCH  /v1/creator-profiles/{creatorProfileId}
POST   /v1/creator-profiles/{creatorProfileId}:set-default
```

### Phase U-3：第三方登录

后续接入：

- 微信登录。
- Apple 登录。
- 企业 SSO。

第三方登录只作为 credential 类型进入账户，不改变版权编号、工作区和创作者档案模型。

## 7. `auth/continue` 迁移策略

当前 `POST /v1/auth/continue` 是研发期接口。产品未正式上线，可以选择直接替换；为了降低双端迁移风险，推荐做一段短期兼容：

- 新客户端使用 `auth/challenges -> auth/sessions`。
- `auth/continue` 保留为开发 / 迁移 alias，内部调用正式 session 创建逻辑。
- 合同测试要求 `auth/continue` 不再成为唯一登录入口。
- 发布前删除或隐藏 UI 中“密码即验证码”的旧逻辑。

验收：

- 桌面端和移动端不再把密码字段同时塞给 `password` 和 `verificationCode`。
- 后端有独立 refresh / logout / me 测试。
- 旧 `auth/continue` 如保留，必须走同一套密码 hash、验证码、设备登记和会话写入规则。

## 8. 版权 ID 服务接入规则

所有在线版权编号 API 必须要求有效 access token。

绑定关系：

```text
watermark_uid
  -> account_id
  -> workspace_id
  -> creator_profile_id
  -> device_id
  -> original_hash
  -> protected_copy_hash
```

API 要求：

- `reserve` 必须校验 workspace 属于当前账号或当前账号有成员权限。
- `reserve` 必须校验 creatorProfile 属于当前 workspace。
- `confirm` 必须校验 watermarkUid 属于当前账号 / 工作区。
- `reconcile` 对离线编号补登记时，若冲突，返回 `conflict` 或 `reissue_required`，不得静默覆盖。
- `reissue` 必须写入 repair job，保留 previous watermark uid 和 replacement uid。

客户端行为：

- 未登录时：离线高熵编号 + `pending_registration`。
- 登录后：同步前自动 `confirm / reconcile`。
- 已登录 Creator / Studio / Enterprise：版权库记录、登记状态、验证记录和报告授权状态自动同步到云端，并自动拉取另一端版权库变更。
- 已登录 Free：可保持账户、权益、报告购买和编号登记上下文；正式双端版权库自动同步由 `cloud_sync=false` 阻断，除非未来 Roadmap 明确调整。
- 登录状态失效：保留本地记录和队列，提示重新登录。
- 设备被撤销：阻止云同步和在线登记，但不删除本地数据。

## 9. 双端 UX 规划

### 桌面端

入口：

- 首次启动：本地使用 / 登录同步双路径。
- 设置：账户、工作区、设备、创作者档案、权益、自动云同步状态。
- 版权库：对 `pending_registration` 提示“登录后补登记”或“重新登录后继续登记”。
- 版权库：Creator 登录后显示“自动同步中 / 上次同步时间 / 待同步数量 / 最近错误”，不把同步藏成手动操作。

关键文案：

```text
本地保护不会因为未登录而停止。登录并开通 Creator 后，版权库会自动同步到你的设备，版权编号可由后端登记确认。
```

### 移动端

入口：
