# HiddenShield 云版权库多用户体系总体设计

更新时间：2026-07-29

状态：`phase_checkpoint_external_gates_suspended`

能力分类：`只能内部测试`

## 1. 决策

云版权库是 HiddenShield 的多用户在线版权记录与协作系统，不是原始媒体网盘、不是“上传任意文件即可判定权属”的检测服务，也不替代国家版权登记、第三方公证或法律意见。

冻结产品模型：

```text
本地版权库（离线优先、完整本机证据）
        ↕ 仅同步白名单 metadata / 审计事件
云版权库（账户、工作区、成员、投影、审计、恢复）
        ↕ 明确授权的公共权利投影
公开权利 Registry / Resolver
```

实现时以 `CloudCopyrightLibrary` 作为深模块。客户端只理解“在某个工作区同步并读取版权记录”；成员鉴权、冲突解决、白名单、事件幂等、审计、投影与数据保留全部封装在模块内部。

## 3. 当前问题与必须修正项

1. 账户、默认 workspace、creator profile 与 entitlement 被压在账户行中，无法表达一个账户加入多个团队、一个工作区多个成员和角色历史。
2. 同步以通用 JSON event 为中心，缺少受版本控制的版权记录投影、字段分类和演进策略。
3. SQLite `Storage` 仍是后端主装配；PostgreSQL repository 和迁移 smoke 不等于生产多租户运行时。
4. 桌面端 refresh token 当前以 JSON profile 落盘；生产端必须改用操作系统安全存储或受设备密钥保护的密文 envelope。
5. 团队共享、工作区切换、权限撤销与离线队列之间没有统一的强一致性语义。
6. 公开权利 Registry、私有云版权记录、AI Transparency Evidence 与付费计量边界尚未拆成独立投影，存在权限外溢风险。

## 4. 目标领域模型

### 4.1 身份与租户

- `Account`：全局登录主体；不直接拥有所有记录。
- `Workspace`：唯一数据租户，类型为 `personal` 或 `team`。
- `WorkspaceMembership`：`account_id + workspace_id` 的独立关系，角色为 `owner`、`admin`、`editor`、`viewer`，带状态、版本、加入/移除时间。
- `CreatorProfile`：账户拥有、可在工作区使用的署名档案；不上传 seed 明文，仅保存受控引用或加密 envelope metadata。
- `Device`：账户下的独立设备与公钥，设备撤销会使 session、同步授权和未完成上传 fail-closed。
- `Entitlement`：账户或 workspace 的商业权益快照；仅决定容量、成员数、保留期、导出和 API，不决定记录所有权。

个人空间是每个账户的默认 workspace。团队空间不复制个人库：记录以 workspace 为租户，创作者署名和记录所有者单独保存。

### 4.2 版权记录与投影

`CopyrightRecord` 是云版权库的私有 metadata 投影，主键为客户端离线生成的 `record_id`。记录必须绑定：

- `workspace_id`、`owner_account_id`、`creator_profile_id`、`origin_device_id`；
- `watermark_uid`、revision、parent UID、media kind、原始/保护副本/取证摘要；
- 作品声明、训练许可、公开权利状态、报告/取证引用；
- `record_version`、`deleted_at`、`classification`、`visibility` 与 server `etag`。

原始媒体、保护副本、缩略图二进制、本地路径、creator seed 明文、access/refresh token、私钥和未脱敏报告附件不得进入该投影。

`PublicRightsProjection` 独立于私有记录；只有用户显式发布后才将最小公开字段写入 Registry/Resolver。`not_found` 仍不代表人类创作、无 AI 使用或无权利争议。

### 4.3 事件、审计与冲突

每个客户端写入先进入本地 outbox，再以 `idempotency_key` 推送 `CopyrightChange`。服务端在一个 PostgreSQL 事务中完成：

```text
membership / entitlement / device 校验
→ 幂等键去重
→ record projection optimistic concurrency
→ append-only domain event + audit event
→ cursor change feed
→ per-event disposition
```

冲突策略冻结如下：

- 同一字段、同一 `base_record_version`：仅一方成功，另一方得到 `conflict_version_changed`。
- 不相交的可合并字段：由服务端字段策略合并，并记录 `merged_by_policy` 与前后摘要。
- 删除与更新、角色撤销与待发送写入、workspace 迁移与写入：一律 fail-closed，保留本地草稿并要求用户重新授权或显式解决。
- 不允许客户端以 last-write-wins 覆盖署名、watermark UID/revision、证据摘要、公开状态、成员权限或审计字段。

## 5. 同步 interface

客户端只依赖一个深 interface：

```text
syncWorkspace(workspaceId, localCursor)
  -> { remoteChanges, dispositions, nextCursor, policySnapshot }
```

内部可拆为 `pushChanges`、`pullChanges`、`resolveConflict`、`changeWorkspace`，但桌面和移动端不得各自实现不同的冲突、白名单或 payload 规则。

统一的 versioned `cloud-copyright-record-v1` Schema 必须生成：

- Rust desktop bridge types；
- Dart mobile types；
- backend request/response validation；
- JSON fixture、桌面写入→移动读取与移动写入→桌面读取 QA；
- 报告摘要和公开权利投影的最小字段。

现有 LAN 直连桌面 HTTP 同步只保留为开发/导入 bridge；不能复用为正式账户、团队或生产同步路径。

## 6. 安全、隐私与恢复

### 客户端

- access token 短期化；refresh token 必须进入 Windows Credential Manager/macOS Keychain/Linux Secret Service/Android Keystore/iOS Keychain，不得再写入普通 JSON。
- 每台设备持有不可导出设备密钥；refresh、设备注册、敏感工作区动作和恢复请求绑定设备身份与 rotation。
- 本地 SQLite 保留媒体路径和完整证据；登出只清云会话和可再获取的云 cache，不删除用户本地版权库。

### 服务端

- PostgreSQL 是唯一生产版权库；SQLite 只允许 fixture、开发和迁移导入工具，不承担生产控制面。
- 每次请求在 repository 入口解析 account/device/membership，所有 workspace 查询都使用 `workspace_id` 条件，并使用 PostgreSQL RLS 或等效强制 repository guard。
- 审计采用 append-only event、actor/member snapshot、request digest、前序 hash 和保留策略；权限变更、导出、公开发布、删除/恢复必须记录。
- 敏感 metadata 使用列级加密或 envelope encryption；KMS key version、解密理由与访问审计必须可追溯。
- 限速、异常设备、批量导出、成员枚举和 cursor 抓取进入安全观测与 incident 流程。

### 恢复

- 备份仅覆盖云 metadata 与审计，不包含默认不上传的媒体。
- 账户恢复、设备替换、workspace owner 转移、成员移除和数据导出均采用双人/受控审批 Gate。
- 删除采用 tombstone + 保留期；保留期过后才可按合规策略物理删除。

## 7. 客户端体验与一致性

| 场景 | 桌面端与移动端统一行为 |
| --- | --- |
| 未登录 | 可使用本地版权库；显示“仅本机”，不暗示已备份。 |
| 登录无权益 | 可查看本地记录；云同步入口解释被权益阻止，不上传。 |
| 个人 workspace | 默认同步 metadata 白名单；显示设备、最近同步、冲突和恢复状态。 |
| 团队 workspace | 明确显示 workspace、成员角色、记录可见性和所有者；切换不迁移记录。 |
| 离线写入 | 先本地成功、进入 outbox；不得显示为“已云端保存”。 |
| 权限撤销 | 立即停止 push/pull；保留本地未同步草稿和原因，禁止继续写入团队投影。 |
| 冲突 | 显示字段级摘要和可操作解决，不静默覆盖。 |

共享水印算法、payload、版权编号生成、重写判断和写后回读仍只能调用 `watermark-core`；云版权库只同步算法产生的结果摘要和验证状态。

## 8. 与 feedback-backend、SDK 和其他能力的联动

### feedback-backend

短期继续使用同一部署进程以复用 auth、device、entitlement、billing、watermark registry 和审计基础，但新增独立 `cloud_copyright` module 与 PostgreSQL adapter。Router 不得再直接将云版权库生产路径绑定 SQLite `Storage`。

长期可在吞吐、驻留或 Enterprise 私有化要求出现后拆为独立部署；拆分前后必须保持 `cloud-copyright-record-v1`、认证和审计语义不变。

### SDK

首期不发布公共“写入云版权库 SDK”。先冻结内部 transport/schema package，供 Tauri、Flutter 与 backend contract test 共用。

- `public-rights-sdk`：只读公开权利查询，不获得私有 workspace 数据。
- AI Transparency SDK：只通过显式 `evidence_link` 关联 confirmed 标识/Manifest；不得读取整库或绕过 membership。
- 未来 Enterprise SDK：使用 workspace-scoped、短期、可撤销 credential；权限、计量和审计独立于终端登录 token。

### 报告、视频和 AI 内容标识

- 报告仅读取被授权的 record snapshot，并固定快照 digest。
- 云视频任务仅保存任务/产物引用和受控下载授权；不因云版权库而默认上传原始媒体。
- AI Transparency 继续保持阶段性挂起；恢复后其 Manifest/Evidence 只能以最小引用写入版权记录，不能提升云版权库或 AI 标识的对外承诺。
