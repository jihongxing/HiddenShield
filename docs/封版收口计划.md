## 1. 封版原则

- 本版只发布 `docs/当前真实能力边界说明.md` 中“可对用户承诺”的能力。
- 不把 L3 视频画面盲水印写成已可售能力；已完成的 L3 release gate、真实 worker、双端产品流、生产 ops dry-run 和 readiness contract 只能作为内部 release candidate 证据。
- 不新增订阅档位、超出既定范围的支付商品、团队管理、云端视频、批量能力或同步字段。
- 新工作只允许属于以下类型：阻断修复、回归测试、运行态 QA、文案边界收口、发布材料、外部联调准备。
- 任何修复不得绕过 `watermark-core`、双端一致性、商业化权益门禁和隐私同步边界。
- Web 预览继续只作为 UI 预览，不进入正式版权库、报告、云同步或跨端 QA 证据。
- 双端能力一致性是封版硬门槛：桌面端和原生移动端必须具备同一套图片 / 音频正式能力；移动端写入 / 加密后的保护副本必须能被桌面端读取、验证或解密出同一版权编号和 payload，桌面端写入 / 加密后的保护副本也必须能被移动端读取、验证或解密出同一版权编号和 payload。
- `field-noise` 稳定噪声底样本当前标记为 RC1 known limitation / release blocker：不得降低 `44 dB` full gate 阈值，不得用单人听感或隔离实验替代自动阈值，不得继续把新频带 writer 实验作为 RC1 主线。

## 2. 本版固定范围

可继续封版的能力：

- 图片盲水印写入、验证和跨端互验。
- 音频盲水印写入、验证和跨端互验。
- 云同步未配置或后端不可用时，图片 / 音频本地写入、回读验证和版权库入库仍可通过本地创作者身份设置完成。
- 双端互解：移动端写入 / 加密的图片、音频保护副本可由桌面端读取 / 验证 / 解密；桌面端写入 / 加密的图片、音频保护副本可由移动端读取 / 验证 / 解密。
- 移动端保护副本保存 / 分享出口。
- 版权库、存证摘要、可信时间展示、本地可读时间与原始回执保留、第三方验证和正式报告。
- Creator 本地批量、正式云同步和正式报告门禁。
- Free 单份报告付费：单份版权详细报告 19.9 元 / 份、维权证据包 49.9 元 / 份；配置真实微信支付通道并完成联调后启用，未配置时展示支付通道未完成配置。
- 匿名反馈、诊断日志和成熟错误提示。
- L1 视频音轨水印。
- L2 视频指纹存证：桌面端完整不可逆 fingerprint bundle -> notary -> vault；移动端 Creator 权益下轻量不可逆 metadata notary 提交；两端都不得把 L2 包装成盲水印命中。
- L3 视频画面盲水印 release candidate：保留 Studio / Enterprise 受控入口、对象上传、trusted worker、自检 receipt、下载入库、双端同步读取和 ops gate 证据；真实告警平台配置验证、首个试点客户签字和更大真实用户 MP4 样本 manifest 未完成前，不进入可售权益、销售材料或正式 SLA。
- 公开权利信号与训练许可声明：版权库、验证页、公开元数据 JSON、图片 / 音频 / 视频传播层、公开扫描 SDK 和 Enterprise 只读批量 API 只表达创作者声明、registry 状态和 `legalConclusion=false`，不得包装成法律授权结论或 AI 生成检测。
- V3/39 默认媒体锚点：图片 / 音频默认写读已使用最小锚点；V2/119 仅保留显式 rollback / 迁移工具链；iOS 同场景 QA 未恢复前，不宣布三端默认 V3 release gate 完成。
- 音频稳定噪声底 known limitation：常规音频与 `transient` 可继续按 release gate 验收，但 `field-noise` 当前仍低于 full gate `44 dB` 客观 SNR 阈值；新频带 writer 实验暂停，不进入本版正式路径。
- 双端验证与报告：桌面端和原生移动端必须对图片、音频、L1、L2、版权库字段、公开权利字段、报告字段、同步 payload、错误码和隐私排除项保持一致。
- Studio 团队空间入口预留和权益边界展示。

冻结到本版之后的能力：

- L3 视频画面盲水印正式产品化。
- 4K / 8K 视频产品线。
- 云端视频处理扣费和 `video_minutes` 正式账本消费。
- 真实团队成员管理、共享版权库操作和团队报告。
- 新订阅套餐、超出单份版权详细报告 / 维权证据包之外的新支付商品、新云同步媒体字段。

## 4. 任务取舍规则

后续遇到新需求时按以下顺序判断：

1. 如果是发布阻断、崩溃、数据泄漏、权益绕过、报告路径泄漏、跨端互验 / 互解失败或错误承诺，优先修复。
2. 如果是体验瑕疵、文案不一致、错误提示不成熟、QA 证据缺口，纳入封版修复。
3. 如果是新能力、新套餐、新云任务、新支付形态、新团队管理、新视频画面水印产品化，默认后置到本版之后。
4. 如果必须改变能力边界，先更新能力边界文档和相关 Roadmap，再进入实现。

## 5. RC1 无外部依赖验收顺序

RC1 的目标不是放宽能力边界，而是在缺少配置项、macOS + Xcode、真实支付、生产 C2PA/TSA、真实告警平台和客户签字的前提下，把当前可本机验证的发布候选状态跑通并记录清楚。

执行顺序：

1. 复跑 `npm run commercial:ci`，确认商业化、双端、共享水印、视频分层、公开权利 production readiness 默认 blocked 合同和基础构建测试仍通过。
2. 串行复跑 `npm run cloud:ci` 与 `npm run cloud-video:ci`，避免并行抢占 `127.0.0.1:43188`。
3. 复跑 `npm run watermark:cross-end-release`、`npm run watermark:quality-gate:release`、`npm run rights:v3-media-payload-release-qa` 和 `npm run rights:runtime-qa`；`watermark:quality-gate:full` 中的 `field-noise` 保持 known limitation / release blocker，不作为 RC1 放行项。
4. 复跑 `npm run public-rights:completion-gate` 和 `npm run cloud-video:l3-production-readiness-contract`，预期默认输出 blocked，并把缺失 artifact 写入验收记录。
5. 补桌面安装版完整人工 QA：图片、音频、验证、版权库、正式报告、云同步、本地批量、L1、L2、公开权利、训练许可、设置反馈、导出日志和关闭后端错误提示。
6. 补 Android 模拟器页面级 QA：图片、音频、验证、保护副本分享、版权库、报告草稿、云同步、本地批量、L1 验证、L2 metadata notary、公开权利和训练许可入口。
7. 将 RC1 结果回写本文、`docs/商业化落地Roadmap.md` 和 `docs/双端能力一致性Roadmap.md`；外部阻断项继续保持 blocked。
