# 音频噪声底跨端可读频带策略迁移设计

更新时间：2026-07-02

本文是 `field-noise` / 稳定噪声底 profile 的下一阶段设计闸门。它只定义迁移方案、兼容规则、双端验证、fixture、回滚和验收标准；在本文验收清单完成前，不进入真正的 `watermark-core` 频带策略迁移实现。

## 1. 背景

`docs/音频噪声底频带选择实验设计.md` 已完成 A/B/C 三组隔离实验：

| 组别 | 结论 |
| --- | --- |
| A `inner_watermark_subband_sparse` | 保持 V3/39 UID 可读和 `extractionConfidence=1.000000`，但 SNR `13.1427 dB`、`bandEnergyShare.watermark.noise=1.000000`，不能晋级。 |
| B `frame_stability_window_sparse` | 保持 V3/39 UID 可读和 `extractionConfidence=1.000000`，SNR 小幅改善，但 `bandEnergyShare.watermark.noise` 仍约 `0.999998`，不能晋级。 |
| C `masked_pair_budget_cap` | 保持 V3/39 UID 可读和 `extractionConfidence=1.000000`，SNR 从同轮 baseline `13.1997 dB` 提升到 `21.1644 dB`，但仍低于 `44 dB`，`bandEnergyShare.watermark.noise=0.999989`，不能晋级。 |

结论：当前 2-8 kHz extractor 可读 lane 内的 lane / 时间窗口 / 单位时间 pair budget 微调应停止。若继续推进，只能进入需要新旧 extractor 兼容和双端迁移验证的频带策略迁移设计。

## 2. 目标

本阶段目标是先证明“可以安全迁移”，不是先改算法。

- 定义稳定噪声底 profile 的新频带策略候选范围。
- 定义新旧 extractor 兼容模型，避免新保护副本只能被单端或新版读取。
- 定义桌面端 / 移动端双向读取迁移验收。
- 固化 fixture、报告字段、失败归因、回滚路径和正式阈值不降规则。
- 明确进入实现前必须满足的设计条件。

## 3. 非目标

- 不改变 V3/39 payload 格式。
- 不改变版权编号格式或签发语义。
- 不降低 `field-noise` full gate SNR `44 dB` 阈值。
- 不把 ABX 单人结论作为自动阈值替代。
- 不在桌面端、移动端、后端或脚本层实现第二套音频盲水印算法。
- 不把迁移研究结果接入正式 UI / mock / release gate 默认路径。
- 不把新频带策略包装成 `Forensic` / `Balanced` 用户可选策略。

## 4. 硬约束

| 约束 | 规则 |
| --- | --- |
| 单一算法源 | 频带策略、写入、读取、payload、提取置信度和回滚判断只能在 `watermark-core` 内实现。 |
| payload 不变 | 新策略仍写入 V3/39 minimal anchor，不新增媒体内权利字段。 |
| UID 不变 | 继续使用完整 128-bit `HS-XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX`。 |
| 跨端可读 | 任一正式端写入的音频保护副本，另一正式端必须能读出同一 UID、payload protocol 和 payload bytes。 |
| 提取不退 | 稳定噪声底 profile 候选必须保持 `extractionConfidence >= 0.99`；常规音频不得低于现有 release/full gate 表现。 |
| 阈值不降 | SNR / LUFS / peak delta / clipping 阈值不得下调；full gate 仍以 `field-noise >= 44 dB` 为解除阻断条件。 |
| 兼容优先 | 新 extractor 必须优先读新策略，同时继续读取当前正式 V3/39 音频保护副本。 |
| 可回滚 | 若新策略导致读取、质量或性能回退，必须能通过 feature flag / payload strategy marker / reader fallback 回到当前正式路径。 |

## 5. 策略版本模型

频带迁移必须引入明确的音频策略版本语义，但不能改变 payload 二进制格式。

建议设计：

| 字段 / 概念 | 规则 |
| --- | --- |
| `audioStrategyVersion` | 只作为保护副本写入侧和报告侧元数据，不进入 V3/39 payload。 |
| `v3_recovery_2_8k_legacy` | 当前正式策略，继续作为默认读取 fallback。 |
| `v3_noise_floor_migrated_band_v1` | 未来候选策略名，仅在实验和 migration gate 内出现。 |
| strategy marker | 如需媒体内 marker，必须放在 `watermark-core` 音频恢复结构内，并证明旧 extractor 失败可解释、新 extractor 可读旧样本。 |
| vault/report 字段 | 记录 strategy version、extractor version、read path、confidence、quality metrics 和 fallback path。 |

禁止项：

- 不得通过复用旧 `WatermarkPayload` 字段塞入策略版本。
- 不得在平台层根据文件名、样本名或 UI 状态猜测策略。
- 不得让移动端和桌面端维护不同 strategy enum。

## 6. 新旧 extractor 兼容规则

迁移必须按“读多写一”的原则推进。

### 6.1 阶段 M0：只读兼容准备

新 extractor 先进入只读候选路径：

1. 尝试读取 `v3_noise_floor_migrated_band_v1`。
2. 失败后读取当前 `v3_recovery_2_8k_legacy`。
3. 再失败后进入既有 V2 / legacy fallback。

验收：

- 旧正式 V3/39 音频 fixture 读取结果不变。
- 当前 release/full gate 中 voice / music / quiet / transient / L1 video audio track 均不退。
- `field-noise` 旧样本仍能读出同一 UID。

### 6.2 阶段 M1：隔离写入实验

新写入只允许通过独立实验入口生成 artifact：

```powershell
npm run watermark:audio-noise-floor-migration-experiment -- --run-id <run-id>
```

该命令尚未实现。实现前必须先完成本文档的 contract 和 fixture 设计。

验收：

- 只对稳定噪声底 profile 触发。
- 产物仅进入 `watermark-core/target/audio-noise-floor-migration/`。
- 不接入正式 UI / mock / release gate 默认路径。
- 每个候选都输出 old extractor / new extractor 的读取矩阵。

### 6.3 阶段 M2：双端只读预发布

桌面端和移动端都升级到新 extractor，但写入仍默认旧策略。

验收：

- desktop old write -> desktop new read 通过。
- desktop old write -> mobile new read 通过。
- mobile old write -> desktop new read 通过。
- mobile old write -> mobile new read 通过。
- iOS 环境不可用时，必须明确记录为未完成，不能用 Android 代替 iOS 承诺。

### 6.4 阶段 M3：受控写入候选

只有在 M0-M2 全部通过后，才允许新策略进入受控写入候选。

验收：

- desktop new write -> desktop new read 通过。
- desktop new write -> mobile new read 通过。
- mobile new write -> desktop new read 通过。
- mobile new write -> mobile new read 通过。
- 新策略写入的保护副本若被旧 extractor 读取失败，必须有明确版本不兼容提示和回滚方案。

## 8.1 新 extractor 读取顺序设计

真正进入新 extractor 实现前，读取顺序先固定为设计合同，不改变当前默认读取路径：

| 顺序 | 读取路径 | 适用范围 | 失败处理 |
| --- | --- | --- | --- |
| 1 | `v3_noise_floor_migrated_band_v1_candidate` | 未来稳定噪声底新频带策略候选 | 失败后不得直接报错，必须进入 legacy V3 fallback。 |
| 2 | `v3_recovery_2_8k_legacy` | 当前正式 V3/39 音频 recovery 策略 | 旧保护副本必须在此路径继续读出同一 UID。 |
| 3 | `legacy_v3_readonly_candidate` | 迁移桥 / 受控 QA reader | 仅用于兼容验证和报告桥接，不作为新写入策略。 |
| 4 | `v2_rollback_legacy` | 显式 rollback / 历史记录读取 | 只允许显式迁移或回滚工具链使用。 |

当前 `manifest.example.json` 用 `plannedExtractorReadOrder` 固化该顺序。`watermark-core` 已导出真实 read-only 候选接口 `extract_audio_noise_floor_migrated_band_v1_candidate_wav_bytes` / `extract_audio_noise_floor_migrated_band_v1_candidate_samples_with_rate` 和 `AudioNoiseFloorMigrationCandidateFailureCode`。`watermark:audio-noise-floor-migration-read-compat` 会先调用该接口；当前已执行 read-only candidate 扫描，旧 V3/39 fixture 预期得到 `candidate_payload_not_found`，随后 fallback 命中 `v3_recovery_2_8k_legacy`，不实现新频带写入策略。

## 8.2 报告字段设计

未来双端报告 / QA JSON 至少要保留以下字段，字段只进入报告和版权库元数据，不进入 V3/39 payload：

| 字段 | 说明 |
| --- | --- |
| `watermarkUid` | 读回的长格式版权编号。 |
| `payloadProtocolVersion` | 必须保持 `3`。 |
| `payloadBytesLength` | 必须保持 `39`。 |
| `audioStrategyVersion` | 写入侧策略版本，例如 `v3_recovery_2_8k_legacy` 或未来候选。 |
| `extractorPath` | 实际命中的读取路径。 |
| `extractorFallbackPath` | 如果发生 fallback，记录 fallback 链路；未发生时为 `none`。 |
| `candidateFailureCode` | 候选读取接口失败码；当前旧 V3/39 样本预期为 `candidate_payload_not_found`。 |
| `candidateScanAttempted` | 是否已执行 read-only candidate 扫描；当前必须为 `true`。 |
| `candidateScanProfiles` | 只读扫描的候选频带 / 时间窗口列表；只用于 read compat artifact。 |
| `candidateFailureMessage` | 候选读取失败说明，只用于 gate / QA 报告，不进入 payload。 |
| `candidateFailureMatrix` | 同一 gate 输出的失败码矩阵摘要，记录每个候选失败码的处理策略、当前观测数和是否阻断。 |
| `extractionConfidence` | 提取置信度，正式候选不得低于 `0.99`。 |
| `readCompatibilityMode` | `legacy_v3_read_compat` / `new_candidate_read` / `rollback_legacy` 等读取兼容状态。 |

当前 `manifest.example.json` 用 `plannedReportFields` 固化字段清单；`watermark:audio-noise-floor-migration-read-compat` 已在每个 fixture 和顶层报告输出 `candidateScanAttempted=true`、`candidateScanProfiles`、`extractorPath=v3_recovery_2_8k_legacy`、`extractorFallbackPath=v3_noise_floor_migrated_band_v1_candidate -> v3_recovery_2_8k_legacy`、`candidateFailureCode=candidate_payload_not_found`、`candidateFailureMatrix`、`readCompatibilityMode=legacy_v3_read_compat_candidate_interface_fallback`。这些字段只代表只读候选扫描和 fallback 证据，不代表新写入策略已经落地。

## 9. 门禁命令设计

迁移实现前，先定义命令边界：

| 命令 | 阶段 | 作用 |
| --- | --- | --- |
| `watermark:audio-noise-floor-migration-contract` | M0 | 检查设计文档、fixture schema、禁止平台层算法和阈值不降。 |
| `watermark:audio-noise-floor-migration-experiment` | M1 | 只生成实验 artifact，不进入正式 UI / mock / release gate。 |
| `watermark:audio-noise-floor-migration-read-compat` | M2 | 当前检查旧策略样本和双端旧产物可被当前默认 extractor / legacy readonly candidate 读取，并通过只读 candidate interface 输出 `extractorPath / extractorFallbackPath / candidateFailureCode / candidateFailureMatrix / readCompatibilityMode`；后续再扩展到真实 new extractor 读取旧样本。 |
| `watermark:audio-noise-floor-migration-release` | M3 | 检查新策略写入候选、双端互读、质量阈值和回滚。 |

任何实现任务不得跳过 `contract` 直接做写入。

## 10. 质量阈值

正式阈值保持不变：

| 指标 | 阈值 |
| --- | --- |
| full gate SNR | `>= 44 dB` |
| release gate SNR | 保持当前 release gate 阈值，不因迁移降低 |
| peak delta | 不高于现有 full gate |
| LUFS delta | 不高于现有 full gate |
| new clipping | `0` |
| extraction confidence | `>= 0.99` |
| UID / payload | 同一长格式 UID、V3/39 |

晋级条件：

- `field-noise` 自动 full gate 解除 `snr_below_threshold`。
- voice / music / quiet / transient / speech-music-mix 不新增阻断。
- L1 video audio track 不新增阻断。
- ABX 只作为补充证据；不能替代自动阈值。

## 11. 回滚规则

必须支持三层回滚：

| 层级 | 回滚方式 |
| --- | --- |
| 写入策略 | feature flag / build-time gate 回到 `v3_recovery_2_8k_legacy`。 |
| 读取策略 | new extractor 失败时继续 legacy extractor fallback。 |
| 记录语义 | vault/report 标记 `audioStrategyVersion` 和 `extractorPath`，避免把候选策略误判为正式默认。 |

触发回滚：

- 任一正式样本提取置信度低于 `0.99`。
- 任一常规音频样本新增 SNR / LUFS / peak / clipping 阻断。
- 双端互读矩阵任一必选项失败。
- 新策略需要平台层特殊处理才能读取。
- iOS / Android / desktop 任一正式端无法解释候选策略结果。

## 12. 失败归因

迁移 gate 必须输出稳定失败码：

| code | 含义 |
| --- | --- |
| `migration_contract_missing` | 设计、fixture schema 或 hard constraint 缺失 |
| `candidate_input_invalid` | 候选读取接口无法解析输入 WAV 或采样参数。 |
| `candidate_audio_too_short` | 候选读取接口收到的音频不足以执行候选读取。 |
| `candidate_not_implemented_no_frequency_strategy` | 候选读取接口已冻结，但新频带策略尚未实现；当前必须 fallback legacy V3。 |
| `candidate_payload_not_found` | 候选读取接口完成扫描但未找到候选 payload。 |
| `candidate_payload_invalid` | 候选读取接口找到候选位流但 payload 校验失败。 |
| `new_extractor_legacy_read_regression` | 新 extractor 读取旧 V3/39 样本回退 |
| `new_strategy_extract_failed` | 新策略写入后新 extractor 不可读 |
| `cross_end_read_failed` | 双端互读失败 |
| `quality_threshold_regressed` | 正式质量阈值回退或新增阻断 |
| `field_noise_still_blocked` | `field-noise` 仍低于 full gate SNR |
| `platform_algorithm_drift` | 平台层出现算法实现或策略分叉 |
| `rollback_unavailable` | 无法回到旧写入或旧读取路径 |

当前 `candidateFailureMatrix` 处理规则：

| code | 当前处理 | 进入算法前约束 |
| --- | --- | --- |
| `candidate_not_implemented_no_frequency_strategy` | 当前不再允许出现；出现即说明 candidate scan 退回 stub。 | 阻断 read compat。 |
| `candidate_input_invalid` | 当前不允许出现；出现即说明输入 fixture 或 candidate WAV parser 回归。 | 阻断 read compat。 |
| `candidate_audio_too_short` | 当前不允许出现；旧 field-noise fixture 必须满足候选和 legacy 读取长度。 | 阻断 read compat。 |
| `candidate_payload_not_found` | 当前旧 V3/39 fixture 的预期观测；旧样本可 fallback，新策略 fixture 必须阻断。 | 只有 legacy fallback 读回同一 UID 且 `extractionConfidence >= 0.99` 才能通过。 |
| `candidate_payload_invalid` | 未来真实候选扫描找到位流但 payload 校验失败；旧 V3/39 fixture 可 fallback，新策略 fixture 必须阻断。 | 在新策略样本引入前，当前观测数必须为 0。 |

## 14. 是否进入实现的决策规则

只有满足以下条件，才进入真正算法迁移：

1. contract、fixture schema、read compat gate 的设计均完成。
2. 已确认平台层不会新增算法分叉。
3. 已确认新旧 extractor 兼容策略不会破坏旧保护副本读取。
4. 已确认 rollback 可用。
5. 已确认 full gate 阈值不降。
6. 已确认双端互读矩阵能在 CI 或受控运行态中落地。

若任一条件不满足，继续停留在设计阶段。
