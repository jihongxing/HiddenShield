# HiddenShield 双端视觉语言迁移实施总计划

更新时间：2026-06-26

本文档是 HiddenShield 桌面端与移动端 UI/UX 重构的执行总线。

本轮迁移不再以“替换颜色、圆角、字体、深色 token”为目标。用户已明确指出上一轮桌面端验收为 0 分，原因是只给旧 UI 套样式，没有复刻 `stitch_hiddenshield_unified_privacy_system` 设计稿里的信息架构、版式骨架、工作流组织和上下文面板。

从本版文档开始，迁移目标升级为：

- 桌面端按 Stitch 设计稿完整重构。
- 移动端采用同一产品模型进行迁移。
- 视觉 token 只作为实现基础，不作为验收结果。

必须继承：

- 暗示 L3 视频画面盲水印已开放的任何表达
- 处理页中的平台分发心智，包括抖音 / B站 / 小红书画幅预设、裁剪 / 黑边和编码模式选择

## 2. 产品重构目标

### 2.1 桌面端目标

桌面端要成为一个版权保护工作台，而不是旧功能页集合。

目标骨架：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 左侧主导航 │ 顶部状态 / 操作栏                                       │
│            ├─────────────────────────────────────────────────────────┤
│            │ 中央主舞台                         │ 右侧上下文面板     │
│            │ 当前工作流、队列、表格、结果        │ 当前对象、证据、   │
│            │                                     │ 权益、下一步       │
└────────────┴─────────────────────────────────────┴───────────────────┘
```

桌面端每个一级页面都必须回答四个问题：

- 当前用户在哪里？
- 当前选中的对象是什么？
- 当前对象处于什么状态？
- 下一步最合理的动作是什么？

如果一个页面不能回答这四个问题，即使颜色与 Stitch 一致，也不算完成迁移。

### 2.2 移动端目标

移动端采用同一产品模型，但不照搬桌面三栏。

桌面右侧上下文面板在移动端转译为：

- 底部 sheet。
- 详情二级页。
- 顶部状态摘要 + 主按钮。
- 当前对象详情区。

移动端目标不是“桌面缩小版”，而是同一工作流的单手任务版：

```text
顶部栏
当前状态摘要
主工作流单列
当前对象卡片
主动作
底部导航
上下文 sheet / 详情页
```

### 2.3 用户体验目标

用户完成核心任务时不应靠猜。

核心任务路径：

```text
选择对象
-> 预检
-> 写入 / 验证 / 存证
-> 完成后验证
-> 版权库入库
-> 报告 / 导出 / 同步 / 购买 / 升级
```

每一步都必须有：

- 阶段名。
- 状态。
- 主要动作。
- 次要动作。
- 失败恢复。
- 权益 / 支付 / 能力边界说明。

## 3. 不可动边界

本计划只重构 UI/UX，不改变能力事实。

必须遵守：

- `docs/商业化落地Roadmap.md`
- `docs/双端能力一致性Roadmap.md`
- `docs/共享水印核心与跨端互验推进计划.md`
- `docs/当前真实能力边界说明.md`

硬边界：

- 不改变图片、音频、视频、报告、同步和权限的真实门禁。
- 不把 Web preview、mock ID 或 QA 编号写成正式版权编号。
- 不把 L3 视频画面盲水印包装成已开放能力。
- 不改变 Free / Creator / Studio / Enterprise 的商业规则。
- 不新增桌面端或移动端单边产品承诺。
- 不把真实微信支付未配置状态伪装成已可真实付款。
- 不把视觉 QA Web 入口当作正式水印能力。
- 不继续把平台分发字段作为版权库产品模型。处理页移除平台画幅、裁剪、黑边和编码模式后，版权库、报告、同步和移动端详情也必须同步改为“保护副本 / 输出策略 / 作品声明与授权策略”。

## 4. 信息架构

### 4.1 一级导航

桌面左侧主导航固定为：

1. 工作台
2. 处理
3. 验证
4. 版权库
5. 批量队列
6. 订阅与权益
7. 设置
8. 帮助与能力边界

移动底部导航固定为：

1. 工作台
2. 验证
3. 版权库
4. 批量
5. 设置

移动端二级入口：

- 处理从工作台主动作进入。
- 订阅与权益从设置、版权库报告门禁、批量门禁进入。
- 帮助与能力边界从设置进入，也可在相关门禁态内直接进入。

### 4.2 模块职责

| 模块 | 用户目的 | 桌面主舞台 | 桌面上下文面板 | 移动转译 |
| --- | --- | --- | --- | --- |
| 工作台 | 开始或恢复任务 | 今日主动作、最近任务、权益摘要、同步摘要 | 当前身份、系统状态、快捷动作、风险提示 | 单列概览 + 主动作 + 状态摘要 |
| 处理 | 写入保护副本或发起视频存证 | 文件选择、预检、流程步骤、进度、完成态 | 当前文件、预检结果、权益、保护副本 / 输出策略 / 分享、失败恢复 | 单流程页面 + 结果 sheet |
| 验证 | 判断文件是否命中版权记录 | 验证输入、结果头、证据指标、匹配记录 | 匹配记录、置信度解释、报告入口、后续动作 | 结果优先页 + 证据详情 sheet |
| 版权库 | 查找和管理版权记录 | 搜索、筛选、表格 / 列表、分组 | 记录详情、保护副本、输出策略、作品声明、时间线、同步、报告、购买 / 导出 | 列表 + 详情页 / sheet |
| 批量队列 | 管理本地批量任务 | 汇总指标、队列列表、全局控制 | 选中任务详情、失败项、重试、暂停 / 取消 | 队列单列 + 任务详情 sheet |
| 订阅与权益 | 理解当前方案和升级路径 | 当前方案、套餐对比、账单状态 | 当前门禁来源、可解锁能力、支付状态 | 设置二级页 + 门禁入口 |
| 设置 | 管理账户、同步、隐私、反馈 | 设置分组与状态 | 当前设置项解释、风险、日志 / 反馈动作 | 分组列表 + 二级页 |
| 帮助 | 理解能力边界和故障恢复 | 能力边界、FAQ、商业规则 | 当前能力状态、相关入口 | 帮助页 + 搜索 / 分类 |

## 5. 桌面端版式骨架

### 5.1 全局壳子

桌面端必须实现稳定的三层布局：

- 左侧主导航：固定宽度，承载模块切换、当前方案简报、主动作入口。
- 顶部状态 / 操作栏：承载页面标题、搜索、同步状态、订阅入口、设置 / 反馈快捷入口。
- 内容区：12 栏网格，中央主舞台和右侧上下文面板并存。

桌面断点建议：

- `>= 1280px`：左导航 + 中央 8 栏 + 右侧 4 栏。
- `1120px - 1279px`：左导航 + 中央主舞台 + 可折叠右侧面板。
- `< 1120px`：不作为桌面主验收尺寸，Tauri 最小宽度仍保持 1120。

### 5.2 左侧主导航

左侧导航不是图标列表装饰，而是产品地图。

必须包含：

- HiddenShield 品牌区。
- 当前方案徽标：Free / Creator / Studio / Enterprise。
- 一级导航。
- 主动作按钮：开始处理。
- 底部区域：同步状态、帮助、设置。

当前选中项必须：

- 有左侧 2px 主色标识。
- 使用高一层 surface。
- 图标和文本同色高亮。

### 5.3 顶部状态 / 操作栏

每个页面顶部必须包含：

- 页面标题。
- 页面一句话任务说明。
- 当前工作区 / 身份。
- 同步状态。
- 搜索或筛选入口，按页面需要显示。
- 订阅与权益入口。

顶部栏不放营销文案，不放大标题 hero。

### 5.4 中央主舞台

中央主舞台承载当前页面的主要任务。

允许形态：

- 工作台主动作 + 最近任务表。
- 处理流程步骤。
- 验证结果与证据指标。
- 版权库表格。
- 批量队列。
- 订阅套餐对比。
- 设置分组。

禁止形态：

- 大量独立卡片堆叠但没有主次。
- 旧页面内容原封不动套深色背景。
- 把所有状态都塞进中央，不使用右侧上下文面板。

### 5.5 右侧上下文面板

右侧上下文面板是桌面端本轮重构的核心验收点。

它必须随当前页面和选中对象变化。

通用结构：

```text
上下文标题
当前对象摘要
关键状态
证据 / 权益 / 风险字段
下一步主动作
次要动作
历史 / 时间线 / 说明
```

不同页面上下文内容：

| 页面 | 右侧上下文必须展示 |
| --- | --- |
| 工作台 | 创作者身份、当前方案、同步状态、最近风险、快捷入口 |
| 处理 | 当前文件、格式 / 时长 / 大小、预检结果、重写风险、权益门禁、输出 / 分享 |
| 验证 | 命中状态、置信度、匹配记录、证据摘要、报告入口、复制摘要 |
| 版权库 | 记录详情、版权编号、创作者身份、完成后验证、第三方验证、可信时间、同步状态、报告购买 / 导出、时间线 |
| 批量队列 | 选中队列、阶段进度、失败项、重试 / 暂停 / 取消、权益门禁 |
| 订阅与权益 | 当前方案、被锁能力、升级后解锁内容、支付状态、退款 / 撤销状态 |
| 设置 | 当前设置项解释、隐私边界、同步白名单、日志导出、反馈入口 |
| 帮助 | 当前能力分类、可承诺 / 内部测试 / 禁止承诺、相关页面入口 |

上下文面板验收标准：

- 选择不同记录 / 任务 / 文件时，右侧内容必须变化。
- 右侧至少提供一个下一步动作，除非当前对象为纯只读说明。
- 右侧不能只是静态广告、说明文本或重复中央内容。
- 右侧宽度在 320px 到 420px 之间。
- 长内容在面板内滚动，不挤压中央主舞台。

## 6. 工作流组织

### 6.1 处理流程状态机

处理页必须按以下阶段组织：

```text
idle
-> selected
-> preflight_running
-> preflight_passed / preflight_blocked / preflight_warning
-> writing / notarizing / fingerprinting
-> write_verified
-> saved_to_vault
-> report_available / report_locked / purchase_required
```

每个阶段必须定义：

- 阶段标题。
- 用户可见说明。
- 主按钮。
- 次按钮。
- 右侧上下文内容。
- 失败恢复。

示例：

| 阶段 | 中央主舞台 | 右侧上下文 |
| --- | --- | --- |
| idle | 文件选择区和能力入口 | 创作者身份、输出目录、权益摘要 |
| selected | 文件摘要和预检按钮 | 格式、大小、时长、历史记录可能性 |
| preflight_running | 进度条和阶段文本 | 正在检查什么、为什么需要等待 |
| preflight_blocked | 阻断原因和替代动作 | 具体字段、可恢复动作、帮助入口 |
| writing | 4px 进度条和阶段文本 | 当前步骤、剩余说明、取消风险 |
| write_verified | 完成后验证结果 | 版权编号、保护副本、分享 / 入库 |
| saved_to_vault | 版权库记录摘要 | 报告、同步、复制摘要 |

### 6.2 验证流程状态机

```text
idle
-> file_selected
-> verifying
-> trusted_match / possible_match / no_match / failed
-> report_action
```

结果展示顺序：

1. 结果结论。
2. 置信度。
3. 匹配记录。
4. 证据摘要。
5. 后续动作。
6. 解释和边界。

### 6.3 版权库详情状态

版权库不是“卡片列表”，而是记录管理工具。

必须具备：

- 搜索。
- 媒体类型筛选。
- 同步状态筛选。
- 报告状态筛选。
- 表格 / 列表密集展示。
- 右侧详情抽屉。
- 时间线。
- 报告购买 / 导出状态。

### 6.4 批量队列状态

批量队列必须以队列方式呈现。

队列项字段：

- 队列名。
- 媒体类型。
- 项目数量。
- 当前阶段。
- 进度。
- 成功 / 失败 / 待处理数量。
- 权益状态。
- 恢复动作。

队列状态：

- 待开始。
- 处理中。
- 暂停。
- 失败。
- 部分完成。
- 已完成。
- 已取消。
- 权益不足。

## 7. 移动端同模型转译

### 7.1 转译规则

| 桌面结构 | 移动结构 |
| --- | --- |
| 左侧主导航 | 底部导航 + 设置内二级入口 |
| 顶部状态 / 操作栏 | 顶部栏 + 当前页面状态摘要 |
| 中央主舞台 | 单列任务流 |
| 右侧上下文面板 | 底部 sheet / 详情页 |
| 表格 | 分组列表 / 可筛选列表 |
| 右侧详情抽屉 | 全屏详情页或半屏 sheet |
| 全局搜索 | 页面顶部搜索框 |
| 多列指标 | 2 列小指标或纵向摘要 |

### 7.2 移动端页面目标

移动端必须保持与桌面相同的产品语义：

- 工作台仍是开始 / 恢复任务的入口。
- 处理仍按阶段推进。
- 验证仍先给结论。
- 版权库仍以记录为核心。
- 批量仍以队列为核心。
- 订阅仍以 Free / Creator / Studio / Enterprise 为共同口径。

移动端不允许：

- 只把桌面卡片垂直堆叠。
- 隐藏关键门禁状态。
- 把右侧上下文内容丢掉。
- 用 Web preview 结果伪装正式能力。

## 8. 页面级施工规格

### 8.1 工作台

桌面目标：

- 左侧导航选中“工作台”。
- 中央上方是主动作区：开始处理、验证文件、查看版权库。
- 中央中部是最近任务 / 最近记录表。
- 中央下方是批量队列摘要或同步摘要。
- 右侧是创作者身份、当前方案、同步状态、风险提示和快捷入口。

移动目标：

- 顶部显示当前方案和同步状态。
- 主动作优先。
- 最近记录和批量摘要单列展示。
- 点任一记录进入详情 sheet。

验收：

- 首屏能看到主动作、当前方案、最近状态。
- 不出现泛化安全模板文案。
- 右侧上下文不是静态说明。

### 8.2 处理

桌面目标：

- 中央左侧为文件选择和流程步骤。
- 中央主区域为预检 / 写入进度 / 完成结果。
- 右侧为当前文件上下文。
- L1 视频音轨水印和 L2 视频指纹存证分层展示。
- L3 明确不开放。
- 输出原则为“最小必要变更”：不提供平台画幅适配、主动裁剪、黑边分发版或多平台优化输出。
- “标记为 AI 生成内容”不作为主流程；应降级为“作品声明与授权策略”，记录创作者声明和训练许可，不包装成 AI 检测。
- 处理页字段变化必须同步到版权库、报告、同步 payload 和移动端详情：不再新增或展示抖音 / B站 / 小红书输出字段，不再用 AI 标记字段作为产品语义。

移动目标：

- 单流程页面。
- 预检结果和写入结果通过 sheet 展示详情。
- 分享保护副本是完成态主动作之一。

验收：

- 用户能看懂当前处于哪一步。
- 预检未完成时不能误导用户立即写入。
- 失败态有恢复动作。
- 页面不再把抖音 / B站 / 小红书、画面裁剪或编码模式作为版权保护主流程。
- 训练许可仍可被记录，但文案必须说明这是用户声明，不是系统判定。
- 新写入记录必须以保护副本和输出策略为核心字段，而不是平台输出。

### 8.3 验证

桌面目标：

- 输入区域与结果区域并列。
- 结果头清楚显示可信命中 / 疑似命中 / 未命中 / 失败。
- 证据指标以 bento / metric 方式展示。
- 右侧展示匹配记录、报告、复制摘要、能力解释。

移动目标：

- App 重启后复制同一条记录的存证摘要，字段仍然完整。
