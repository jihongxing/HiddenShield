# 音频 V3 强度与噪声段处理调参任务

更新时间：2026-07-02

## 1. 背景

`npm run watermark:quality-gate:full -- --run-id codex-full-smoke` 已生成完整感知质量报告和 ABX 模板。图片样本、常规音频样本和 L1 视频音轨样本通过；音频样本 `field-noise` 与 `transient` 被客观 SNR 阈值阻断：

- `field-noise`：SNR `8.94 dB`，低于 `44 dB` 阈值。
- `transient`：SNR `43.52 dB`，低于 `44 dB` 阈值。

单人主观听感复核结论是两类样本人耳几乎无法分辨差异，但该结论不能替代正式 5 人 ABX，也不能绕过 full gate 的客观阻断。

## 2. 目标

- 在不降低正式质量阈值的前提下，降低 `field-noise` 与 `transient` 场景的可测失真。
- 保持 V3/39 payload、版权编号、跨端读写和恢复规则不变。
- 保持图片、常规音频、L1 视频音轨现有通过状态不回退。
- 如果继续依赖主观不可感知解释，必须完成 5 人 ABX 并把结果回写到 full gate 证据。

## 3. 候选方向

- 噪声段处理：识别低信噪比 / 噪声底主导片段，对嵌入强度做上限收敛，避免在 `field-noise` 这类样本里放大客观 SNR 偏差。
- 瞬态保护：对鼓点、脉冲、点击声和快速起音片段降低或跳过嵌入能量，优先在稳定帧中分摊 payload。
- 能量感知强度曲线：按短时 RMS、频带能量和静音 / 近静音状态选择强度，避免对弱能量区间产生不成比例扰动。
- 指标解释校验：如果发现 `field-noise` 的低 SNR 主要来自原始样本本身能量极低或噪声底特性，应把指标解释与 ABX 结论分开记录；不得直接调低阈值放行。

## 4. 非目标

- 不降低 `docs/盲水印无感测试计划.md` 中定义的正式 SNR 阈值来制造通过。
- 不改变 V3 payload 格式、版权编号格式或跨端 fixture 结构。
- 不把 Forensic / Balanced / 调参强度作为用户可选择商业功能暴露。
- 不把单人听感复核包装成 full gate 通过。

## 5. 验收标准

- `npm run watermark:quality-gate:release -- --run-id <run-id>` 通过。
- `npm run watermark:quality-gate:full -- --run-id <run-id>` 中 `field-noise` 与 `transient` 不再因 SNR 阈值阻断；若仍阻断，必须附 5 人 ABX 统计结论和继续 blocked / exception 的明确判断。
- `watermark-core` 提取、恢复和跨端验证不回退，桌面端 / 移动端读取同一保护副本仍能恢复同一 copyrightId 与 payload。
- `watermark-core/target/perceptual-quality-full-gate/<run-id>/quality-full-gate.md`、`abx/audio_abx_trials.csv` 与 `docs/封版收口计划.md` 回写最新结论。

## 6. 推荐执行顺序

1. [x] 固化当前 baseline：保留 `run-codex-full-smoke` 报告、JSON、ABX CSV 和样本文件。
2. [x] 为 `field-noise` 与 `transient` 增加调试指标输出：短时 RMS、低能量帧比例、瞬态帧比例、嵌入强度分布和提取置信度。
3. [x] 先实现噪声段 / 瞬态段强度收敛实验，不改 payload 和正式 UI。
4. [x] 复跑 release gate 与 full gate，对比 baseline 的 SNR、LUFS、peak、提取成功率和样本级结果。
5. 如果客观指标仍无法通过，再组织 5 人 ABX，并按 `docs/盲水印无感测试计划.md` 的通过 / 阻断规则决定是否继续调参。

## 7. 第一轮实验记录

执行时间：2026-07-02

实现内容：

- V3 recovery lane 写入改为自适应目标对比度：按短时 RMS、noise-like 频谱和瞬态判定收敛强度。
- 相对频带 pair 改为最小必要改写：如果当前 pair 已满足目标 bit 和边际，不再强制重分配左右能量。
- readonly candidate 提取顺序改为优先 V3 recovery，再回退 V2 legacy，避免 V3 样本误入 V2 tolerant 纠错长跑。
- full gate 音频 JSON / Markdown 增加 `metrics.debug` 与 `Audio V3 Debug Metrics`。

验证结果：

- `npm run watermark:quality-gate:release -- --run-id codex-v3-audio-v3-first-release` 通过。
- `npm run watermark:quality-gate:full -- --run-id codex-v3-audio-v3-first-full` 仍 blocked。
- `transient`：SNR 从 baseline `43.52 dB` 提升到 `54.9592 dB`，通过 full gate，extraction confidence `1.000000`。
- `field-noise`：SNR 从 baseline `8.94 dB` 提升到 `12.5383 dB`，仍低于 `44 dB` 阈值，releaseBlockingReason 仍为 `snr_below_threshold`，extraction confidence `1.000000`。

结论：

- 第一轮强度收敛有效修复瞬态样本，并保持 V3/39 payload、版权编号、跨端读取语义和 release gate 不回退。
- `field-noise` 的阻断不是提取失败，而是噪声底样本中相对频带改写对客观 SNR 仍过重；不能通过降低阈值或单人听感直接放行。
- 曾尝试更激进的 raw-bit majority 稀疏写入，但会导致 `voice` / `quiet` 提取失败或长时间提取，不进入本轮实现；后续若继续走稀疏编码，需要同步设计新的提取窗口与纠错策略。

当前推荐下一步：针对 `field-noise` 单独设计 V3 recovery 稀疏写入 + 对应提取窗口实验，目标是在保持 extraction confidence `>= 0.99` 的前提下，把 modified pair ratio 从约 `0.568` 继续压低，而不是继续全局降低强度。

## 8. 噪声底稀疏写入实验记录

执行时间：2026-07-02

实现内容：

- 新增稳定噪声底 profile 判断：中等 RMS、RMS 动态范围很小、低能量帧比例低、瞬态帧比例低，并存在 noise-like 频谱比例；不按 `field-noise` 样本名硬编码。
- 当 `noiseFloorSparseRecovery=true` 时，V3 recovery bit-slot 不再修正全部 3 条 lane，而是只修到提取端 3-lane majority 可读出的最少 pair。
- payload 格式、版权编号、V3/39 recovery packet、质量阈值和正式 UI 均未改变。
- full gate 音频 debug 增加 `noiseFloorSparseRecovery` 字段。

验证结果：

- `npm run watermark:quality-gate:release -- --run-id codex-noise-sparse-final-release` 通过。
- `npm run watermark:quality-gate:full -- --run-id codex-noise-sparse-final-full` 仍 blocked。
- `field-noise`：`noiseFloorSparseRecovery=true`，modified pair ratio 从约 `0.568` 降到 `0.282321`，extraction confidence `1.000000`，SNR 从 `12.5383 dB` 小幅提升到 `13.5115 dB`，仍低于 `44 dB` 阈值。
- `transient`：继续通过 full gate，extraction confidence `1.000000`。
- release 常规音频与 L1 视频音轨未触发 noise-floor sparse profile，保持通过。

结论：

- 该实验达到“降低改写比例且提取置信度不退”的目标。
- 该实验没有达到“解除 `field-noise` SNR 阻断”的目标；full gate 仍必须保持 blocked。
- 继续沿 lane 稀疏化本身收益有限，下一步应判断 SNR 计算是否需要更符合噪声底素材的分段解释，或改造 V3 recovery 的噪声底专用频带 / 时间分布，而不是降低 `44 dB` 阈值。

当前推荐下一步：对 `field-noise` 做分段 SNR / 频带能量差异诊断，确认低 SNR 是由全频宽噪声底统计放大、特定频带能量重分配，还是实际可听失真造成，再决定是否进入噪声底专用频带选择实验。

## 9. field-noise 分段 SNR / 频带能量诊断记录

执行时间：2026-07-02

实现内容：

- `watermark:quality-gate:release` / `watermark:quality-gate:full` 的音频与 L1 视频音轨报告新增 `metrics.perceptualDiagnosis`。
- `perceptualDiagnosis.segmentedSnr` 按 1 秒窗口记录 min / mean / max / first / middle / last / spread。
- `perceptualDiagnosis.bandEnergyShare` 按 low `20-1500 Hz`、watermark `2000-8000 Hz`、high `8000-16000 Hz` 记录原始信号能量占比和保护副本差异能量占比。
- Markdown 报告新增 `Audio Perceptual Diagnosis` 表，便于人工 review 直接判断是全频宽噪声底统计放大、特定频带能量重分配，还是没有客观证据指向可闻失真。
- 本轮只读诊断不改变 payload 格式、版权编号、V3/39 recovery packet、跨端读取规则、提取置信度计算或质量阈值。

验证结果：

- `npm run watermark:quality-gate:release -- --run-id codex-field-noise-diagnosis-release` 通过。
- `npm run watermark:quality-gate:full -- --run-id codex-field-noise-diagnosis-full` 仍按预期 blocked。
- `field-noise`：SNR `13.4966 dB`，仍低于 `44 dB` 阈值；modified pair ratio `0.284046`，`noiseFloorSparseRecovery=true`，extraction confidence `1.000000`。
- `field-noise` 分段 SNR min / mean / max 为 `10.8940 / 13.7845 / 16.2193 dB`，spread `5.3253 dB`。
- `field-noise` 原始信号 low / watermark / high 频带能量占比为 `0.474960 / 0.373096 / 0.151943`；保护副本差异噪声 low / watermark / high 占比为 `0.000001 / 0.999998 / 0.000001`。
- `field-noise` 的 `dominantNoiseBand=watermark`，诊断为 `specific_watermark_band_energy_redistribution`。
- `transient` 继续通过 full gate，SNR `55.0830 dB`，extraction confidence `1.000000`。

结论：

- `field-noise` 低 SNR 不是提取失败，也不是当前诊断下的全频宽噪声底统计放大；差异能量几乎全部集中在 watermark 频带。
- 自动诊断没有证明存在人耳可闻失真；它只能说明客观 SNR 阻断的主要来源是特定频带重分配。
- 质量阈值必须继续保持 blocked，不能用单人听感或诊断解释绕过 `44 dB` SNR 阈值。
- 下一轮若继续推进，应进入“噪声底专用频带选择实验”，目标是在保持 payload / UID / 跨端读取 / extraction confidence / 质量阈值不变的前提下，把 field-noise 的差异能量从当前 watermark 频带集中状态迁移到更符合噪声底掩蔽的频带或时间窗口。

当前推荐下一步：设计 `audio_noise_floor_band_selection_experiment`，只对稳定噪声底 profile 生效，比较 3 组候选频带 / 时间窗口的 SNR、bandEnergyShare、extraction confidence 和 ABX 记录，不降低任何正式阈值。

## 10. 噪声底专用频带选择实验设计

执行时间：2026-07-02

设计文档：`docs/音频噪声底频带选择实验设计.md`

设计边界：

- 实验代号为 `audio_noise_floor_band_selection_experiment`。
- 只允许稳定噪声底 profile 触发，触发条件沿用当前 `watermark-core` 噪声底 profile 语义，不按 `field-noise` 样本名硬编码。
- 可晋级候选必须保留现有 `audio_band_bins`、recovery bit-slot、3-lane majority 和当前 extractor 可读布局；需要新 extractor 才能读回的频带迁移只能作为研究对照。
- 三组候选为 `inner_watermark_subband_sparse`、`frame_stability_window_sparse`、`masked_pair_budget_cap`，分别比较子频带 lane 优先级、稳定时间窗口选择和单位时间 pair budget 上限。
- 每组必须输出 SNR、`bandEnergyShare`、`segmentedSnr`、`modifiedPairRatio`、`extractionConfidence` 和独立 ABX 记录。
- payload 格式、版权编号、跨端读取、提取置信度门槛和正式质量阈值均不得改变。

设计结论：

- 优先实现 `frame_stability_window_sparse`，因为它只改变稳定噪声底 profile 下的时间窗口选择，最有机会在保持现有 extractor 可读的前提下改善分段 SNR。
- 若 SNR 仍低于 `44 dB`，full gate 继续 blocked；ABX 只能作为补证，不能替代自动阈值。

当前推荐下一步：实现独立实验入口 `watermark:audio-noise-floor-band-selection-experiment`，先只生成实验 artifact，不接入正式 UI / mock / release gate 默认路径。
